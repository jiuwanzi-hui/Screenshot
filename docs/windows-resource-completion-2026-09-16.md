# Windows 操作结束后的资源释放检查

范围：普通截图、长截图的交接／编辑／预览、钉图与编组、OCR 结果窗口、文字翻译。仅改动 Windows 工程；不修改长截图的采集与拼接算法。

## 修复

- 关闭普通截图、预览和编辑器时解除图像绑定、清空识别层与大文本缓存，并取消尚未完成的文字任务。
- 长截图预览关闭时同步清空待呈现帧，拒绝关闭后到达的后台帧，防止取消与预览更新竞争后重新持有长图。
- 长截图的初始化也纳入清理范围；启动失败、取消和首次帧交接失败会释放初始图像、窗口和输入事件订阅。
- 编辑器和历史保存共用冻结的 WPF 图像。后台准备一次预览后打开编辑器，移除历史保存所需的整张 GDI 克隆及第二次 WPF 转换；原始像素与历史内容保持不变。
- 历史 PNG 编码结束后再次申请合并回收，覆盖后台保存晚于窗口关闭的情况。历史正常保存后仅保留缩略图和路径；写盘失败仍保留原图，避免丢失用户数据。
- 钉图、编组关闭时清空合成图、成员引用、文本层和识别结果。编组保留合成图至 `Closed` 处理完成，确保管理器能先将编辑结果应用回成员。
- 钉图和编组的翻译、识别与表格补充识别传递生命周期取消信号；关闭后停止任务并忽略迟到结果。编组关闭不关闭其成员钉图。
- OCR 结果窗口关闭时取消正在进行的翻译请求；文字翻译窗口关闭后不再接收语言变更、延迟翻译或进度回写。

继续使用已有的按事件合并、非阻塞内存回收和约 10 秒模型工作进程空闲退出，不清空／限制工作集，不降低图片分辨率或模型质量。

## 三轮独立进程测量

使用实际 `App` 启动入口及独立默认配置，测试图像仅离屏处理。每轮创建一张 1440×10000 长图，生成编辑画布、添加马赛克并导出；保存原图与编辑结果到历史；创建并关闭普通截图窗口、预览、两张钉图与编组。每轮关闭后等待 40 秒，给应用原有合并回收及后台 PNG 保存留出时间。

使用弱引用跟踪每轮 13 个窗口／图像对象；三轮空闲检查均未发现这些对象仍然存活。测量过程没有测试专用的强制 GC，也没有清空工作集。资源是否可回收的单元测试会使用测试专用 GC，与这里的进程测量分开。

Windows 性能计数器每约 3.5 秒采样一次，MiB = 1,048,576 字节：

| 状态 | 专用工作集 | 总工作集 | 专用提交量 |
| --- | ---: | ---: | ---: |
| 大图处理期间的一次采样 | 265.09 MiB | 381.27 MiB | 297.38 MiB |
| 第二轮空闲的一次采样 | 48.12 MiB | 171.67 MiB | 82.06 MiB |
| 第三轮结束后最后一次采样 | 50.44 MiB | 175.02 MiB | 84.78 MiB |

这些是采样值，不能当作精确峰值。三轮未发现整张长图或窗口的累计保留，但 **40 MB 静默后台目标仍未达到**。不能将专用工作集、总工作集和提交量混为同一个数字，也不能从本机结果推断用户 16 GB／Iris Xe 电脑的准确数值。

测试边界：本次循环验证窗口、图像编辑／导出和历史保存的生命周期；没有操纵真实网页执行全程滚动采集，没有改变用户剪贴板。真实多屏、不同 DPI 及长时间交互仍需用户环境复核。仍显示的钉图或尚未关闭的编辑器会保留当前文档必需的图像。
