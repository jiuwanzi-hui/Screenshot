# Windows 网页悬浮内容截图修复（2026-09-14）

## 原因与修改

普通键盘截图原先先显示透明全屏窗口，再从后台获取首帧。即使窗口不主动激活且透明，显示窗口仍可能改变鼠标命中，让网页收起悬浮卡片。原有的原生菜单截图缓存无法覆盖网页内部的 DOM 悬浮内容。

现改为在后台取得首帧并绑定冻结图片后才显示截图窗口。普通截图、识别、翻译的交互入口及延迟取图的选区入口共用此顺序。已有的菜单缓存继续使用。等待取图时保持窗口隐藏，支持全局 Esc 取消；仍使用有超时、单个采集任务限制和迟到帧释放的首帧服务。显示后的输入就绪与遮罩交接检查保留。

不在输入钩子中同步采集，不增加常驻截图缓存或轮询。

## 验证

- Release 构建成功。
- 定向回归：23 通过，0 失败，3 个依赖真实桌面输入的菜单测试按项目默认跳过。
- 覆盖隐藏取图期间没有截图 HWND、界面线程可响应、Esc 取消、重复调用不增加采集任务，以及首帧超时、迟到帧释放、缓存画面发布与输入就绪检查。
- 尚未在客户具体网页上实测。网页自身在修饰键按下时主动关闭内容的情况，不等同于截图窗口显示造成的鼠标离开，需具体页面确认。

复查方式：保持鼠标停在网页悬浮卡片上，按截图快捷键，框选卡片后分别识别、翻译；同时检查 Esc 取消与再次截图。
