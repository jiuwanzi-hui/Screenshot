# Windows Medium、设置打开与截图交接验证

日期：2026-09-18。仅 Windows；未修改 macOS、长截图算法或线上发行状态。

## 改动

- 默认高质量 OCR 从 PP-OCRv6 Small 切换为 Medium，检测、识别模型与 RapidOcrNet 预设一起更换。四份文件实际下载并核对长度及 SHA-256；合计 139,842,893 字节，约 133.4 MiB。仍在按需启动的独立 OCR 工作进程中执行。
- 更新后的后台启动检查，只以完整旧 Small 安装为迁移依据。先持久化待提醒状态，再删除四个已知旧模型文件；保留未知文件和其他模型，不遍历目录链接。文件占用时记录原因，下次启动重试。已装 Medium 不提醒；第一次安装且没有旧模型不提醒；旧用户看到提醒后不重复弹出。
- Medium 在原尺寸小字条上可能只识别中文，漏掉英文或数字。先保留原尺寸识别，对短边不超过 96 像素、检测文字高度不超过 28 像素的小字条增加最多一次 2 倍补识别。仅当原有非空白字符全部按序保留且有新增文字时采用补充结果。沿用原有空结果放大重试，最长边 800、短边 400 的输入预算不变；阈值不变，不更改保存图片，坐标映射回原图。
- 设置首次显示期间暂时解除鼠标低级钩子，避免桌面鼠标消息等待同一界面线程构建窗口；窗口完成布局后恢复。保留键盘快捷键；处理嵌套打开、延迟恢复与关闭竞态。模型及更新状态刷新移到窗口绘制后；设置工作进程使用独立、短时后台 JIT 启动配置，不常驻预加载窗口。
- 截图工具栏交接时，旧原生截图画面临时归属于遮罩窗口，形成“旧画面 > 遮罩 > 编辑窗口”的所有权关系。原先同属编辑窗口的两个兄弟窗口可能被系统重新排序，导致半透明遮罩再次压暗旧画面。现在即使出现迟到的置顶操作，旧画面仍保持最上方；提交与取消时恢复原有所有者。另阻止已带选区的交接路径执行初始框选层绘制。

## 测试

环境：Windows 11，10.0.26200；Intel Core Ultra 7 270K Plus，24 核，约 64 GB 内存。以下耗时不能代表反馈者的 Ryzen 7 4800H 或更老电脑。

- 设置交互、快捷键、OCR 迁移、模型初始化错误、定位与语言等针对性回归：88 通过、4 桌面用例默认跳过。
- 即时设置与功能进程协议：66 通过、5 桌面用例默认跳过。
- 实际 Medium 工作进程和小字回归：14 通过。覆盖冷启动、连续复用、10 秒空闲后退出、再次加载、取消、失败后恢复、模型原始初始化异常；父进程没有加载 ONNX。
- 原生遮罩的离屏窗口回归：2 通过。覆盖迟到置顶、解除临时所有权、销毁遮罩不销毁另一进程的旧画面，以及不变选区不重复重绘。
- 真实桌面交接回归：已验证预先准备和未准备工具栏的冷／连续路径，另验证跨进程输入接管与提前取消。四次像素采样最大 RGB 变化均为 0；跨进程交接后编辑窗口可接收输入，关闭后工作进程约 2.1 秒退出。没有显示测试色块或注入全局鼠标输入。
- 本机交接样本：未准备 580/159 ms；已准备 103/96 ms。跨进程样本为已准备 196 ms、未准备 285 ms。这些计时范围不同，不应直接横向比较。
- Medium 620×110 混合文字样本：冷加载 547 ms、连续 146 ms、空闲退出后重新加载 521 ms；总工作集及其峰值均为 295.6 MiB，私有提交量 262.0 MiB。这里只测量该工作进程和该样本，不是整个应用或所有图片的内存上限。
- `mixed-ocr-host-selection.png` 的 2/4/6/8/12/16 线程实测均得到相同的 12 个文字块；第二轮分别为 1.90/0.82/0.52/0.40/0.37/0.52 秒。保留当前机器 8 线程预算，避免 16 线程造成退化；受控线程数不能替代旧 CPU 实机验证。
- 最新源码 Release 实际启动后，原 Small 目录已清理，Medium 保留，迁移标记为 notified（本机已有新模型，无需下载提醒）。

## 用户提供的艺术字图片

实际对比原始 235×329 图片，使用完整 Small / Medium 模型与产品阈值。Medium 原尺寸和 2 倍均未识别；额外诊断中，3 倍仅识别“牛”，4 倍出现“色房”等误识别，库默认预处理也有错字。Small 同样无法完整识别。

因此这张描边、竖排、彩色艺术字图不能作为 Medium 可用的正例，不能承诺切换后可以识别。不降低阈值、不预填答案；3/4 倍诊断仅用于比较，没有加入产品重试。样图未复制进仓库或交付包。
