# Windows 空闲进程与临时功能拆分（2026-09-16）

本次仅修改 Windows `Screenshot.App` 和 Windows 测试，不修改 macOS，也不调整长截图采集／拼接算法。

## 问题与证据

上一轮关闭窗口对象、清理缓存后，仍没有满足接近冷启动内存的要求。用户报告设置或自动识别关闭后约 100～120 MB。此次读取用户运行的源码 Release 进程 PID 50728：专用工作集 98.13 MiB、总工作集 229.21 MiB、专用提交 197.94 MiB。取转储之前采样，避免转储过程改变工作集。

转储中没有存活的 MainWindow 或 CapturedImage 实例；托管对象总量约 5.1 MiB，GC 提交约 12.2 MiB。继续只处理窗口引用或请求 GC 无法让同一 WPF 进程卸载已经加载的界面／原生运行库及其分配器。转储分析摘要保留在 `artifacts/windows-idle-host/user-heap.txt`。验证后删除转储的操作被自动审批策略拦截，因此 233,522,991 字节的 `user-idle.dmp` 暂时留在本机，不作为交付附件。

## 实现

- 默认入口启动常驻部分：单实例、快捷键、托盘及用户启用的悬浮按钮。设置、截图、编辑、识别、翻译、视频与钉图在同一按需启动的功能进程运行。
- 当前用户专用的随机命名管道，并核对连接进程 PID。临时截图帧传原始像素行与屏幕坐标，不采用有损压缩，不保留整屏大缓冲池。
- 功能进程准备就绪后才接管快捷键；退出或异常终止后常驻部分重新注册，并加载保存的配置。保留鼠标长按参数、指针续接、设置页签及本次运行的上次截图区域。启动期间 Esc 可取消待发送的截图，连续请求合并／串行交接。
- 功能窗口、钉图（包括隐藏钉图）、录屏、设置中的下载以及尚未完成的保存／导出阻止空闲退出。全部结束后事件触发一次约 2 秒的检查，与常驻部分握手确认没有新请求后退出。设置原有关闭清理约 2 秒，因此设置关闭至功能进程退出通常约 4 秒。
- 剪贴板写入、历史图片落盘、视频导出、录制器释放、预览释放等持有操作计数，不能因窗口先关而截断写入或原生收尾。整个应用退出时先停止录屏并保留持久钉图，再完成退出。
- 截图首帧等待常驻悬浮按钮确认隐藏；首帧仍在截图层显示之前取得。不同进程保存窗口位置时合并写入，避免互相覆盖。
- 没有清空工作集、设置工作集上限、周期重启常驻进程或添加周期性阻塞 GC。常驻 PID 在所有测试轮次中不变。

## 实际测量

Release，Intel Core Ultra 7 270K Plus / 约 63.4 GiB 物理内存 / RTX 5070 Ti。可复现探针在独立输出目录使用独立配置，运行真实 App 的常驻／功能分支；设置及视频窗口透明、不激活，其他大图主要离屏渲染。未通过人为 GC 或工作集裁剪压低采样。

口径为 Windows `WorkingSetPrivate`，另列总工作集和专用提交；不能把这些数值混称为任务管理器同一列。功能及模型进程退出后的空闲结果只有常驻进程，因此没有把占用转移到未统计的功能进程。活动期间多进程合计峰值未作为本轮完整基准，资源 CSV 不用于声称 OCR／翻译峰值或显存上限。

离线翻译另行在功能进程中实际加载 Hy-MT2-1.8B，译文包含预期的“保存”和“窗口”。刻意保留会话至进程结束，确认原生推理进程随功能进程退出，没有等待其 10 秒空闲定时器，也没有留在后台。CPU/GPU 加载、取消、再次使用另由运行时回归覆盖。

结果已接近冷启动，仍有约 4～10 MiB 常驻增量，不能承诺任意机器每次精确回到 33 MB。活动功能首次启动增加约 0.4 秒（本机测量），不同硬件需另测；没有宣称低配、高配或所有主题均相同。

### 当前用户配置的实际桌面复验

最终源码 Release 常驻 PID 57672，使用用户原有“墨湾流光”主题、悬浮按钮及快捷键配置，没有改写配置。启动稳定后专用工作集 41.86 MiB。通过 Windows computer-use 在源码目录窗口按现有全局快捷键 Alt+C，实际打开设置（功能 PID 10040），随后关闭设置。功能进程确实退出，常驻 PID 57672 保持不变，关闭后稳定为 42.31～42.33 MiB，距该次启动约 +0.45 MiB；总工作集 144.48 MiB、专用提交 71.11 MiB。只剩一个 SnapCut 进程，没有残留测试或推理进程。证据在 `started-process-settled.json` 和 `actual-settings-close-final.csv`。
