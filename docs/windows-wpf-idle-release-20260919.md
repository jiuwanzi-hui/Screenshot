# Windows 界面进程恢复空闲释放（2026-09-19）

用户确认取消后台 WPF 常驻，优先降低待机内存。本轮保持 4.1.7-localtest，不发布在线更新。

## 行为

- 移除“保持截图界面就绪”的运行逻辑、设置项和内存压力监听。旧配置里的 `keepCaptureUiReady: true` 作为未知字段忽略，正常保存时移除；其他配置保留，不重置设置。
- 最后一个窗口/钉图关闭、截图或录屏等任务结束后，界面子进程约 2 秒请求退出。父子进程核对最新命令编号和任务状态后才退出，避免空闲退出与新快捷键发生竞争。
- 活动窗口、最小化但未关闭的设置、钉图、正在进行的任务仍然保留。退出前完成待保存配置。托盘和悬浮入口继续运行。
- 原生框选及触发时并行准备界面的路径保留；窗口、工具栏 UI 和操作不重构。保留上一轮原生热键消息窗口改动。OCR/离线翻译独立进程的短时复用与释放策略不变。

这是撤销整个界面运行环境的常驻，不是将界面运行环境压缩到小工具栏大小。空闲后需要重新加载 WPF，4800H 首次工具栏等待的问题不能据此宣称解决。没有清空工作集、修改工作集上限或反复强制 GC。

## 验证

- Release 构建成功；既有 SettingsViewModel CA1859 提示仍在。
- 配置迁移、管道协议、退出与新命令竞争、原生消息窗口和快捷键回归：27 项通过。
- 实际窗口/子进程回归：14 项通过，包含截图和录屏工具栏、框选取消、焦点恢复、2/8 逻辑处理器预算及热键交接。
- 8 次实际工具栏关闭后，界面进程自行走正常退出协议，退出码为 0；从关闭命令到进程退出为 2099–2173 ms。测试最终清理中的强制终止仅用于失败兜底，成功断言在此前完成。
- CPU 预算测试运行于本机，不等于 4800H 真机复测。计时是程序协议阶段，不等于摄像机测得的物理松手至显示时间。

小体积日志与实际退出计时在 `artifacts/wpf-idle-release-20260919`。最终附件和包校验见 `docs/releases/4.1.7-localtest-validation.md` 的本轮记录。

最终正常托盘进程实测：旧配置开启过常驻，打开设置保持活动后关闭，界面子进程约 4.06 秒退出；托盘继续运行，10 秒后的专用工作集约 31.3 MiB、私有提交约 63.2 MiB。设置自身有约 2 秒隐藏复用阶段，之后再进入界面进程的约 2 秒空闲退出。只有一个 SnapCut 进程，没有强制工作集清空。最终成品 8 项真实工具栏/退出和更新 61 项回归通过；本轮打包暂存已清理。
