# Windows 4.1.7 取色反馈、工具变体与表情栏

日期：2026-09-20。仅修改 Windows，版本号沿用 4.1.7，未打包发布。

## 取色视频调查

检查了用户提供的 6.64 秒手机拍摄视频；取色面板移动时可见条带残留，约 6.1 秒的框选边缘不明显，问题在工具栏出现前已存在。对应 resident 的原生 GDI 取色／框选阶段，不能归因于工具栏 WPF 首显。

本机尚未复现该用户的偶发异常，显卡、驱动、Windows、HDR、多屏信息尚未取得。现有离屏重绘回归覆盖原图不变、拖动恢复原色、前后两帧损坏区域恢复、主题边框、桌面边缘取色和 100%–200% 缩放，不能据此宣称该用户机器已修复，也不能断言显卡损坏。

后续补充：用户确认 4.1.5 正常、4.1.7 异常，提供 RTX 5070 Ti / 4K 160 Hz 信息后，扩展连续移动到高 DPI，已复现并修复新版宽描边未计入重绘范围的残留缺陷。此前高 DPI 用例只验证静态绘制，未覆盖连续移动。详见 `windows-picker-dpi-regression-20260920.md`；目标机完整现象仍待复测。

代码中确认存在错误处理缺口：原先忽略 GDI 资源创建、复制原始像素、遮罩、边框、刷新及呈现的失败结果，局部重绘结束后仍记录为有效帧。现已检查这些返回值；失败帧不再作为下一次局部重绘的有效底图，原生窗口发生异常时立即隐藏并结束此次操作。增加了故障注入回归，确认失败后需完整重绘，恢复的像素与全新绘制一致。此项是防护修正，尚无证据证明它就是视频根因；没有默认关闭硬件加速或改动截图原始颜色。

相关 API 的返回语义参见 [AlphaBlend](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-alphablend) 与 [FrameRect](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-framerect)。证据保存在 `artifacts/windows-selection-shift-20260920`，未对外上传用户视频或截图。

## 工具切换

- 截图和录屏标注的当前工具可单独按下、松开左／右 Shift 循环底部按钮选项，复用实际菜单动作，保持选中状态、保存偏好、绘制工具和主图标同步。
- 覆盖矩形／椭圆、四种箭头、实心／空心双向箭头、直线／波浪线、两种马赛克、文字背景等实际提供的按钮组。录屏保留其既有工具范围。
- 长按不连跳；组合键、鼠标拖动／滚轮、文本与下拉输入、焦点丢失不触发切换。序号编辑器、翻译语言选择和表情滚动列表不误作工具变体按钮组。
- 工具栏仍是精简后的 WPF 实现；原生的是前期框选与取色，不能称全部工具栏已原生化。

## 表情布局

- 表情改成单行水平滚动列表，保留完整目录、彩色图像和按钮提示；鼠标滚轮浏览超出部分。
- px 滑块和值在表情右边，右下状态文字预留宽度。录屏同步采用此布局。
- 展开选项保持当前工具栏位置，仅在屏幕边界处作必要限制，不因新高度重新跳到选区另一侧。
- 仍按需构建表情，不增加空闲驻留、轮询或缓存；保留界面进程空闲退出策略。
