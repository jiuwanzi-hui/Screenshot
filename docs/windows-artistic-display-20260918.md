# Windows：艺术字在显示缩放与选区边距下的识别恢复

2026-09-18，沿用 4.1.7-localtest。只修改 Windows 共用 OCR 层，截图、钉图及翻译使用同一结果；不修改截图像素、macOS 或长截图算法。

## 已复现的原因

同一六字样本原图曾通过，显示缩放或增加选区边距后仍会出现漏列和“房”。之前仅验证原图不足以覆盖用户实际操作。

- 增强触发条件限制最短边 400 像素；图片显示到 175% 后超出限制，Medium 没有被调用。
- 增强结果必须保留 Small 全部字符并增加字数。Small 已误认的字符，或者两次识别的繁体异体字不同，会阻止整段结果替换，连另一列新增的正确文字也丢失。
- 竖排重排后，大字可能被检测成多个独立框；旧恢复要求单框而拒绝该结果。另一个带边距样本把整列误判成置信度 0.851 的单个“房”，超过旧恢复入口的 0.8 上限。

## 修改边界

- 普通文字仍使用 Small。仅最大边不超过 1000、像素数不超过 480,000，且首轮为空或少量疑似竖排文字，才允许按需调用 Medium；完整网页不受此增强路径影响。
- 按区域位置合并增强结果：新增区域必须经过完整竖列验证；替换重叠区域要求置信度提升，已有较强结果和无关文字保留，不再要求错误字符原样留下。置信度证据只在工作进程内部使用，不进入 UI／管道公共数据。
- 对过大的竖排重排条带，首次假设不合格时只允许一次 128 像素高的归一化重试。字符坐标先还原至重排条带，再映射回原图；保存和钉图仍保留原始像素。
- 原输出 0.45、完整竖列 0.8 阈值不变。对于几何上有多个字符而原结果不完整的列，可检查置信度低于 0.9 的原假设；只有候选达到 0.98 且提升至少 0.1，才允许使用这条额外纠错规则。其他恢复仍要求提升 0.15。不硬编码样本答案。
- 保留每图最多 4 个竖列恢复、工作进程短暂复用和约 10 秒空闲退出；不空闲预加载模型。

## 真实样本与限制

回归读取用户本机原图和最新反馈截图，不把私人图片嵌入仓库或发行包。覆盖 100%、125%、150%、175%、200%，每档 0／8 像素边距，以及最新反馈截图中的实际显示区域；同时检查六个文字位置在原图内、原图像素不变。

这些样本能恢复“鼠虎猴”和“牛兔鶏／鷄”，不再只输出“房”或漏掉另一列。最后一个繁体／异体字仍不能视为准确识别。测试通过仅说明已覆盖样本和边界，不能保证任意艺术字或所有缩放比例都准确。

艺术字缩放矩阵复用同一进程，首次 833 ms，后续 204–563 ms；实际反馈截图的图像裁剪也恢复两列。普通网页仍为 93 个区域、连续文字一致，和前轮 2.070／1.511 秒基本一致。600×100 小选区连续约 53 ms。这些不是低配电脑的时延保证。

单独原图测试的艺术字工作进程总工作集 444.8 MiB、峰值总工作集 445.1 MiB、专用提交 491.7 MiB；连续缩放矩阵后的进程为 622.0／625.8／998.2 MiB。两者口径相同，均非专用工作集或主程序空闲占用。约 10 秒空闲后观察到工作进程真实退出；取消实际增强识别后也退出，后续重新识别结果和字符坐标一致。不依靠清空工作集制造回落。
