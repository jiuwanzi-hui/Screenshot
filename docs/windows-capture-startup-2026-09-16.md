# Windows 截图首次响应优化（2026-09-16）

范围仅 Windows。保留常驻快捷键进程和按需功能进程；没有修改 Mac、长截图拼接算法、截图分辨率、OCR 模型或用户配置。

## 原因和改动

功能进程每次重建后，原先依次执行设置读取／迁移、管道设置解析、原生辅助窗口初始化、WPF 界面构造、桌面抓取和首帧呈现。进程拆分释放了窗口所属的运行库，但让这些冷启动开销重新进入每次截图的关键路径。

- 功能进程在 Application 加载 XAML 时就连接管道、解析主进程已校验的设置。迁移和启动注册仍由常驻进程处理，不在每次截图重复执行；子进程接管输入前才注册快捷键，交接时设置若已变动仍发送最新值。
- 管道使用生成的 JSON 元数据，保持原有完整设置、枚举、图像像素和屏幕坐标的表示。
- 首帧抓取与原生／WPF 窗口构造并行。隐藏悬浮按钮的确认及后续继续执行不占用界面线程；抓取线程等待桌面合成刷新，拿到原始像素后才显示、激活截图层。
- `PendingCaptureFrame` 管理提前取得的唯一首帧：窗口取得后接管所有权；Esc、构造失败和原生调用迟到均释放图像，保留一次抓取上限与超时。
- 截图功能进程使用 .NET 的短时后台 JIT 编译顺序缓存。首帧可交互后停止收集；取消／失败最多收集 3 秒。缓存是本地方法顺序文件，不含截图或模型，也不需要驻留功能进程。第一次没有缓存仍走正常路径；只读目录及单核环境兼容回退。API 行为依据 [Microsoft ProfileOptimization.StartProfile](https://learn.microsoft.com/en-us/dotnet/api/system.runtime.profileoptimization.startprofile?view=net-8.0)。

## 本机实测

2560×1440、125% 缩放；独立探针使用默认主题和独立配置，没有保存实际桌面截图。使用真实功能进程、截图界面和首帧输入就绪检查，每轮关闭后确认进程退出，再发起下一轮。

| 阶段 | 第 1 次 | 第 2 次 | 第 3 次 |
| --- | ---: | ---: | ---: |
| 修改前：请求到截图层显示 | 771 ms | 699 ms | 734 ms |
| 并行设置／首帧，未启用编译顺序缓存 | 584 ms | 573 ms | 572 ms |
| Release：请求到截图层显示 | 599 ms | 488 ms | 475 ms |
| 同轮 Release：请求到原生输入检查完成 | 663 ms | 580 ms | 585 ms |

修改前从主进程转发入口计时；最终 Release 从 `App.SendFeatureAsync` 开始，包括待保存配置刷新。两者均不包含测试工具或键盘驱动的输入注入耗时，不能称为所有机器的物理按键到显示保证。第 1 轮没有编译顺序缓存，后两轮功能进程仍是重新启动。不是将功能进程留在后台来得到热启动数值。

这组探针常驻进程启动专用工作集 32.31 MiB，三轮关闭并空闲后 44.65 MiB；对应总工作集 130.68 → 157.53 MiB，专用提交 63.10 → 76.73 MiB。三个功能进程均退出，常驻 PID 17440 未变。仍有协议、快捷键及运行库初始化增量，不承诺精确恢复到启动数值，没有清空工作集。

原始计时、内存 CSV、构建及回归输出在 `artifacts/windows-idle-host/startup-*`，探针源码在该目录 `Program.cs`。测试不替代不同硬件、显示驱动和实际鼠标持续操作的验收。

## 回归

新增提前首帧的交接、构造失败、Esc 取消／迟到释放、失败传播测试，以及生成 JSON 与旧协议完整等价检查。首轮针对性测试 26 通过、0 失败。

Windows 完整回归 1768 通过、97 按默认规则跳过、0 失败。最终管道交接实测通过：并发请求共用进程、异常退出恢复快捷键、启动中取消、活跃任务期间不退出、重新启动保留上次截图区域。

补充限制两颗逻辑核心（进程亲和性及 `DOTNET_PROCESSOR_COUNT=2`）的最终版本回归：截图层显示 626／560／519 ms，输入就绪 724／676／619 ms；三轮功能进程全部退出。该结果只代表本机受控 CPU 预算，不等同于真实低配 CPU、低内存或不同显示驱动。

用户当前配置的源码 Release 实例也已启动并核对路径：常驻 PID 15588，墨湾流光主题、Alt+A、自动识别配置保持原样，设置文件 SHA-256 前后一致。通过实际全局 Alt+A 启动功能 PID 9312，Esc 后确认其退出，常驻进程不重启。启动专用工作集 42.14 MiB，取消后稳定约 40.09 MiB；未通过该次 UI 自动化测量物理按键到像素的延迟。对应 `startup-user-before.json`、`startup-user-after.json`、`startup-user-process.json`。

最终构建使用普通 Release，不启用截图／输入诊断符号；没有发布、推送、版本号变更或常驻预加载截图界面。
