# 4800H 工具栏系统跟踪分析（2026-09-19）

## 结论与修订范围

已找到目标电脑上可以落到调用栈的冷启动成本：界面线程等待 WPF 完成图形初始化，同时还要执行 .NET 即时编译、窗口及输入初始化。这些工作会在空闲功能进程退出后重新发生。现有证据不支持把完整延迟归结为工具栏最后一次 Show、CPU 线程数太少或显卡排队一秒。速度问题尚未完成目标机修复验证。

这轮修复了采集脚本成功却误报失败的问题，并补齐已有的显式软件/硬件渲染参数向功能进程传递的缺口，方便直接验证图形初始化这部分成本。默认渲染策略不变；没有自动切换用户机器的渲染方式，没有改变 OCR、翻译、编码的计算设备、模型或线程预算，没有扩大常驻内存，也没有改动 Mac 和长截图算法。

## 输入文件与采集误报

`ToolbarSystemTrace-20260919-102450-1899dc.zip` 中 ETL 为 193,986,560 字节，SHA-256 为 `27C5FD20B04487D472815B3D90DBA0C3714E1B4333F5C3DD9A19BBAAE9B9D0E0`，与目标电脑元数据一致；WPR 日志明确写着保存成功。

父脚本在 Windows PowerShell 5.1 中未先保留进程句柄，`WaitForExit()` 后得到 null 退出码，再把 `null -ne 0` 当成失败。本机对真实退出 0/7、中文/空格路径共 54 次无害子进程复现验证，保留 Handle 后结果正确。生产函数另在 PowerShell 5.1/7 各通过 7 项成功/失败/产物校验回归。已提供的 ETL 有效，无需因为这个误报重录。

## 已证实的等待

工作进程 PID 18252，UI 线程 TID 39136，WPF 渲染线程 TID 29972。公共系统符号按 ETL 中的 PDB 标识匹配，本地解析，没有上传用户跟踪或源码。

| UI 等待区间（相对跟踪开始，ms） | 时长 | 同期渲染线程工作 |
| --- | ---: | --- |
| 19635.03–19842.48 | 207.46 ms | Direct3DCreate9Ex、AMD/NVIDIA 驱动加载，NVIDIA 路径中有证书读取校验 |
| 20642.13–20800.19 | 158.06 ms | D3D 设备和硬件队列创建，驱动及叠加组件初始化 |
| 20970.97–21042.43 | 71.46 ms | 着色器编译、透明窗口像素输出 |

三段合计 436.97 ms，UI 均停在 `CMilConnection::SynchronizeChannel → CMilChannel::SyncFlush → MilComposition_SyncFlush`，由渲染线程完成后唤醒；唤醒后的调度延迟均不足 0.01 ms。渲染线程同期主要在用 CPU 计算，最长已观察到的直接 GPU 同步等待约 2.77 ms。因此不能称为显卡堵住一秒，也没有依据要求用户更换驱动、禁用安全校验或提高 OCR 线程数。

其他启动工作同样明显：19.842–20.642 秒这 799.65 ms 内，UI 有 599 个约 1 ms 的 CPU 样本，其中 167 个调用栈包含 JIT；20.800–20.971 秒的 170.78 ms 内有 161 个 CPU 样本，其中 50 个包含 JIT。另有窗口创建、输入/IME、类型和元数据处理。样本计数不是精确函数墙钟耗时，尚不能可靠分摊到某一个 XAML 控件。

## 记录限制

循环缓冲已经覆盖部分早期内容。线程切换记录保留在 15.954–25.517 秒，DWM 仅保留 25.358–26.147 秒；保存时 CLR rundown 大量占用共用事件缓冲。Windows 原生事件读取已交叉验证时间，不能把 `EventsLost=0` 当成历史全部保留。

PID 18252 缺少进程启动前缀，但保留了上述图形初始化及相邻 UI 工作。后来的 PID 30880 有进程开始事件，却缺少调用栈和线程切换记录。这份包没有鼠标松开标记，所以上述时间不能冒充完整“松手到工具栏”的耗时；采样本身也有开销。

## 针对性对照

现有 `--software-rendering` / `--hardware-rendering` 原来只作用于主进程，功能进程会丢掉它们，不能用这种启动方式验证截图工具栏。已统一解析显式选项并传给功能进程，同时让诊断日志记录实际 WPF 渲染模式。普通启动仍自动选择原来的路径。

先用同一份 10:15 便携程序直接启动真实功能进程做对照，覆盖截图/录屏、2/8 逻辑处理器预算、快速框选、取消、输入与进程退出，每种模式 8 项通过。本机快速框选从进程创建至呈现：

| 功能 / 处理器预算 | 硬件界面渲染 | 软件界面渲染 |
| --- | ---: | ---: |
| 截图 / 2 | 820.8 ms | 772.8 ms |
| 截图 / 8 | 831.5 ms | 777.1 ms |
| 录屏 / 2 | 707.7 ms | 635.6 ms |
| 录屏 / 8 | 721.7 ms | 631.5 ms |

这里只证明本机存在小幅差异，不能推广为 4800H 已解决。软件渲染也会增加绘制期间的 CPU 工作，不宜未经目标机验证设为全局默认。本次同版本测试包提供两个独立启动入口，记录模式和阶段耗时；不修改设置，不修改系统注册表。退出后正常打开即恢复默认路径。对照应使用便携包，避免安装版计划任务提权丢掉临时参数。
