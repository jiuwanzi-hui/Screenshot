# Windows 离线翻译启动隔离、设备缓存与耗时验证（2026-09-20）

后续反馈：用户已确认 GTX 1650 Ti 成功使用 GPU，新的 15.4 / 7.0 / 5.7 / 7.1 秒延迟反馈、进一步调度优化和最新验证见 [Windows 翻译延迟记录](windows-translation-latency-20260920.md)。下文保留当时的启动故障排查与测试数据。

## 证据与限制

用户 GTX 1650 Ti 4 GB / AMD 核显电脑在 4.1.7 中出现 Vulkan 探测 20 秒超时、CPU 回退后启动总时限耗尽，原生日志为空。可用内存 15,935,197,184 字节、16 逻辑 / 8 物理核心，CPU 负载约 1.3%。这不能证明内存、显存不足，也不能确定驱动损坏。此前设置空 `GGML_VK_VISIBLE_DEVICES` 仍会创建 Vulkan 实例、枚举物理设备，CPU 与显卡初始化并未真正隔离。

本次仍未在该 GTX 1650 Ti 电脑上复现原始驱动卡点。修正的是已确认的回退、运行库校验、重复探测与错误取证问题，不能宣称目标电脑 GPU 已恢复或 6 秒目标已经实现。

## 实现

- 从 SHA-256 固定的原 b10276 ZIP 创建 `inference-b10276/cpu` 与 `vulkan` 运行目录。CPU 只包含服务器、核心 DLL、OpenMP 和各 CPU 指令集后端，不带 Vulkan/RPC。不删除旧模型或运行库，不增加下载，不改变模型精度。组件与可信 ZIP 逐一校验，同长度损坏可修复；原子替换和跨进程文件锁防止启动半写入文件。
- 清除子进程的额外 `GGML_BACKEND_PATH`；仅在本程序的无界面计算子进程中禁用 Vulkan 隐式叠加层，保留 ICD 和显式层。这是兼容处理，不是认定目标故障由叠加层引起，不修改系统环境或驱动设置。
- Vulkan 探测从 20 秒改为 3 秒。原生进程创建可取消，迟到进程自动结束；探测进程和模型工作进程都使用退出即终止的 Job Object。没有原生输出的工作进程 8 秒后结束，不再一直消耗正常模型加载的 90 秒总预算。有输出的正常加载仍保留低速机器的加载预算，不把慢速推理硬截为 6 秒。
- 记录失败阶段、PID、退出码、CPU 时间、内存和模块名称及有界原生输出。GPU 失败而 CPU 恢复时也保留这次实际故障；正常探测/翻译不写诊断，取消不记录故障，进入推理前停止启动日志，不存原文或译文。
- `TranslationModels/inference-hardware-b10276.json` 保存机器指纹、CPU 拓扑、所选 Vulkan 设备等稳定信息。两个模型共用，跨界面进程退出及应用重启复用；指纹含机器、CPU、当前 DXGI 适配器及 LUID、驱动版本、OS 和运行库/策略版本，不包含明文机器标识。设备、驱动变化或实际加载失败使旧结果失效；系统重启或驱动重建设备造成 LUID 变化时也需重新确认一次，避免把旧 Vulkan0 编号误用于其他显卡。失败探测仅缓存 10 分钟并显示“沿用上次探测结果”，不伪装为无显卡。
- 当前内存/CPU 负载及 WDDM 显存预算只按需读取。WDDM 返回的是本进程的操作系统分配预算，不能当作全局物理空闲显存的精确值；预算不足或不明使用一任务/原生适配，实际分配失败保留 GPU fit / CPU 回退。重复名称适配器取最小预算，避免镜像/虚拟适配器导致错误放大。
- 轻量模型在约 3.5 GB 预算、内存有余量时可使用两路并发；最终仍按模型权重、上下文、任务数量和系统负载收紧。4 GB 显存紧张不使用旧余量，不改变用户选择的模型、语言或提供方顺序。保留约 10 秒空闲进程退出。

## 验证

开发机 Core Ultra 7 270K Plus / RTX 5070 Ti 16 GB，Windows 10.0.26200；不是用户的 GTX 1650 Ti。原始运行输出在 `artifacts/windows-translation-loader-20260920`。

- `regression.log`：59 通过、5 个需单独环境开关的用例跳过；其中 7 个真实原生案例实际运行（Hy-MT2 / TranslateGemma × GPU / CPU，损坏模型，探测卡住，缓存复用）。更新并发预算后 `final-unit.log` 59 通过、9 个显式集成入口默认跳过，已运行的原生案例另见上述日志。
- CPU 真实翻译时检查进程模块，确认没有 Vulkan loader 或 backend；两种模型均能实际中英互译，取消后能重启，空闲约 10.2 秒实际退出，失败释放工作进程。
- 模拟原生探测输出后卡住 30 秒，3 秒截止；转入真实 Hy-MT2 CPU 翻译，开发机共 4.16 秒完成短句，保留故障输出并确认探测进程退出。这个短句数字不是整页性能。
- 新建两个独立会话/管理器，第二次将探测委托设置成“一旦调用即失败”，实际 GPU 翻译仍通过。两次含短句翻译约 1.93 / 1.64 秒，确认读取磁盘缓存而非依赖上一个工作进程。
- WDDM 身份/预算首次约 51 ms、重复约 1.1 ms；CPU 拓扑由持久化缓存复用。4 GB 有余量和紧张预算、驱动指纹变化、缓存过期/损坏、旧动态空闲值不持久化均有回归。
