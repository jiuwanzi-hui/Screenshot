# 4800H 工具栏等待：现场诊断

## 当前状态

用户确认 21:17 包在 Ryzen 7 4800H 上仍然慢。目前实际通过远程控制测试，“本地应该也慢”尚非本地对照证据。上一轮 bootstrap 字段丢失是已验证的真实缺陷，但不能据此宣称目标电脑的剩余延迟已解决。本轮收集目标机器的完整链路，不再用高端本机的局部耗时替代结论。

## 诊断数据

- 常驻进程：截图触发、子进程创建、首帧取得、原生框选显示、实际收到鼠标松开消息、最终命令发送、交接完成及工作进程退出。
- 功能进程：进程入口和应用 XAML、bootstrap、主题／WPF 渲染等级／渲染模式／远程会话标志、工具栏构造与隐藏 HWND、实际缩放、原始像素读取与冻结预览、消息入队到 UI 派发、实际显示和屏幕合成交接。
- 录屏单独记录辅助窗口、录制器构造、控件接入、Show/布局、呈现等待、驻留画面释放和设备枚举，避免把不同阶段统称为“工具栏慢”。
- 每事件附进程累计 CPU 时间、总工作集、专用提交、缺页总计数、Gen2 次数和线程池待办数。CPU 是进程累积值，缺页包含软缺页，不能单凭计数判定磁盘问题；无常驻采样线程或计数器轮询。
- 各进程使用同机 QPC 及频率排序；记录程序构建 MVID、版本和执行文件 SHA-256，排除同版本文件混淆。收集脚本在启动前读取 CPU、内存、显示器和显卡驱动信息，不在用户截图时执行 WMI 扫描。

这些时钟从目标程序收到消息起计时，不能测量远程客户端物理松键到目标机收到输入的延迟，也不能替代远程编码和传输测量。SystemParameters.IsRemoteSession 对第三方远程软件未必为 true，须结合用户说明，而非以该字段单独否定远程场景。

## 收集操作

退出现有 SnapCut，将本次便携包解压覆盖原便携程序文件，保留 ScreenshotData／模型和现有主题配置。双击程序同目录的 Start-ToolbarDiagnosis.cmd。按控制台说明，在日常截图的软件中测试：等待 15 秒截图、马上连续截图、再等 15 秒截图；再等 15 秒框选录屏区域并取消，不必启动录制。最后托盘退出 SnapCut，回到控制台按 Enter。

控制台显示 ScreenshotData/Diagnostics/ToolbarTrace-时间-标识.zip 的实际路径。该 ZIP 只收集本次捕获阶段日志、hardware.json、timeline.csv、summary.md；没有截图像素、识别文字、键盘输入、用户设置和密钥，不自动上传。需要用户将它发回本任务，才能继续针对实际最长阶段定位。

诊断只由用户运行收集器启用，有最长 15 分钟期限，子进程继承同一个截止时间。日志后台批量写入，每进程文件轮转限制约 10 MiB。收集完成还原／移除本次开关；若用户中途关闭控制台，记录仍会到期停止。正常 Release 不读取标志文件，不包含 Mark/UiContext 调用；本次诊断包是 4.1.7 本地测试交付，禁止发布为正式更新。没有额外修改 OCR、翻译、长截图或 Mac。

## 本机验证范围

- 带诊断构建的 38 项相关回归通过，包含真实截图／录屏窗口、隐藏工具栏、帧传输、防闪和退出测试；未注入全局输入。之后补充旧格式 enabled 标记用例，正常 Release 的 18 项通过，包含禁止诊断调用的 IL 检查。
- 收集／导出脚本在 PowerShell 7、Windows PowerShell 5.1 均通过：跨进程 QPC 排序、已知 500 ms 延迟、取消缺失确认不伪造结果、无关设置／截图文件排除。
- 现场日志目录选择、过期、损坏开关、目录越界及 15 分钟上限有回归。实际子进程日志已核对 CPU／内存、构建标识、主题和录屏阶段记录。
- 本机成功不代表 4800H 已定位或修复。最终诊断包及附件校验记录在 releases/4.1.7-localtest-validation.md；现场日志尚待用户提供。
