# Windows 翻译资源释放与钉图状态提示

## 结论

修复了已结束翻译通过服务定时器继续引用截图窗口的泄漏，缩短了离线推理进程的空闲退出期限，并将钉图翻译状态移到颜色／线宽控件右侧。

**40M 后台目标尚未通过验收。** 完成真实 OCR 和两次轻量翻译、关闭截图窗口后，隔离默认配置探针测得专用工作集约 45 MiB；总工作集约 170 MiB，专用提交量约 78 MiB。模型进程退出、窗口可回收，不等于主进程所有已使用的运行库和分配器内存都已归还。不得用这次修复宣称所有机器、所有使用场景均低于 40M。

本次只修改 Windows。未修改 macOS、长截图采集和拼接算法、用户模型或提供方顺序。

## 已确认的泄漏

修改前对本机正在运行的 Release 进程取堆转储，发现两个截图窗口仍在堆中；其中已关闭窗口存在以下强引用链：

```text
LocalLargeTranslationModelManager
  -> LocalTranslationInferenceSession
  -> _idleTimer / TimerQueueTimer
  -> ExecutionContext / AsyncLocal
  -> 已 Dispose 的 TranslationProgress
  -> 进度回调闭包
  -> CaptureOverlayWindow
```

推理会话首次在翻译期间创建。定时器捕获当时的执行上下文；即使模型工作进程已经退出、进度对象已标记结束，回调字段仍引用窗口。

修复如下：

- 服务定时器统一通过 `BackgroundTimer` 创建，禁止携带创建时的执行上下文。覆盖离线大模型、OCR、Mozilla 离线翻译、延迟设置保存及合并内存回收定时器。
- `TranslationProgress.Dispose` 释放回调、同步上下文及前一个进度引用；保留结束标志，忽略迟到状态，重复释放不会清除更新的翻译作用域。
- 两种离线大模型共用会话空闲期限从 30 秒缩短为约 10 秒。空闲回调核对最后使用时间，避免旧回调关闭刚使用的进程；与推理通过同一锁串行。
- CLD3 检测器按需创建，空闲约 10 秒后释放检测实例；新请求重新创建，保留相同检测规则。不手工卸载仍可能被托管绑定使用的原生 DLL。
- 普通截图、钉图、图片编辑和录屏工具栏的完整表情列表改为打开面板时加载；连续打开复用当前窗口中的控件。既有空闲表情缓存释放继续生效。
- 设置附近的说明更新实际空闲退出期限，不把模型文件大小当成运行内存。

## 钉图翻译提示

- 状态与颜色／线宽放在同一个布局行，右对齐、垂直居中，与普通截图一致。
- 长状态最多显示两行，连续空白合并；鼠标悬停可查看完整换行说明。空状态隐藏。
- 离屏回归检查共同父布局、所在列、对齐、两行高度和完整提示内容，没有在用户桌面显示测试图案。

## 验证

测试机：Intel Core Ultra 7 270K Plus，24 核／24 线程，约 64 GiB 内存，RTX 5070 Ti。CPU 路径显式禁用模型 GPU 设备。没有用户截图中 16 GB／Iris Xe 笔记本的实机验证。

### 代码与资源回归

- Release 编译成功。
- 定向回归 **260 通过，0 失败，5 跳过**。涵盖进度作用域、定时器上下文、窗口和图像资源、设置保存／隐藏窗口、表情像素一致性、空闲调度、钉图状态、通用复合词翻译与截图恢复。5 项跳过为需显式启用的本机模型用例；没有把它们算作通过。
- 独立启用真实轻量模型生命周期测试 **2 通过**（CPU、GPU）。检查实际翻译、连续复用、取消后的进程退出、自然空闲退出、重新加载及失败后的进程退出。
- 独立启用 OCR 工作进程测试 **5 通过**。验证原始像素管道、截断输入拒绝、首次／连续识别、取消恢复、实际退出及再次加载；主进程未加载 ONNX。
- 未运行依赖全局输入和真实抓屏的桌面集成测试；没有改变录屏或长截图算法。

### 实际轻量模型进程

模型为 Hy-MT2 1.8B；加载和正文计时分开记录。以下是本机测试结果，不作为低配机器速度保证：

| 路径 | 加载 | 首次正文 | 连续正文 | 最后请求结束到实际退出 |
| --- | ---: | ---: | ---: | ---: |
| CPU | 1108 ms | 1515 ms | 375 ms | 约 10.2 s |
| RTX 5070 Ti | 1997 ms | 2040 ms | 42 ms | 约 10.2 s |

进程观察器等待退出，不能仅由内部进程字段为空判断释放。测试期间 CPU 工作进程采样专用提交量约 1134 MiB、总工作集约 2142 MiB；GPU 工作进程约 3585 MiB／336 MiB。这些是进程内存采样，**不是峰值、不是显存用量**。

PP-OCRv6 Small 的另一组真实识别：首次 349 ms，连续 60 ms，退出后重载 332 ms；空闲退出和取消恢复均通过。

### 主进程内存测量

专用工作集由 Windows 进程性能计数器读取，总工作集和专用提交量分别记录。MiB = 1,048,576 字节。后台测量没有清空／限制工作集，没有设置 GC 堆硬上限。

| 场景 | 专用工作集 | 总工作集 | 专用提交量 |
| --- | ---: | ---: | ---: |
| 修改前本机正在运行的用户配置进程 | 142.7 MiB | 310.7 MiB | 312.6 MiB |
| 最终 Release 用户配置冷启动采样 | 约 42.7 MiB | 约 140.1 MiB | 约 72.3 MiB |
| 修复后隔离默认配置、悬浮按钮、冷启动 | 约 31.4 MiB | 约 130.5 MiB | 约 62.3 MiB |
| 同一隔离探针完成 OCR／两次翻译并关闭窗口后 | 约 45 MiB | 约 170 MiB | 约 78 MiB |

修改前进程有用户此前的操作历史，不能与隔离冷启动作等价对比或据此报告降幅百分比。

隔离探针使用实际 `App`、托盘和悬浮按钮，独立保存默认设置；创建离屏截图窗口，在其进度作用域中完成 1920×1080 样图的真实 OCR 与两次轻量翻译，再关闭窗口。通过应用原有捕获状态入口进入／结束工作，等待原有空闲清理。关闭窗口和图片的弱引用在测试强制 GC **之前**已失效；后续堆检查没有遗留截图窗口实例。

弱引用诊断的额外强制 GC 仅用于测试，不加入产品，也不采用诊断 GC 之后的数据宣称满足后台指标。样图未显示在桌面。

最终启动路径为 `src/Screenshot.App/bin/Release/net8.0-windows10.0.19041.0/SnapCut.exe`，已核对实际进程路径。临时诊断目录 `artifacts/windows-memory-audit` 的递归清理被自动审批以“blocked by policy”拦截；已改为仅清理明确列出的三个转储文件，其余临时探针、工具和结果保留在该目录，不进入发行产物。

仍需继续验证和降低的部分：主程序使用过 UI、翻译协议和语言检测后仍有运行库／分配器开销；真实用户配置、反复打开设置／编辑／录屏等完整生命周期尚无统一 40M 达标证据。现有结果只能确认本次泄漏修复与工作进程退出，不能将单次隔离样例推广为全部功能资源验收。
