# Windows 截图工具架构设计

## 1. 目标与边界

本项目是 Windows 10/11 的轻量截图常驻工具。首版目标是让用户能以低延迟完成框选截图、复制、保存、编辑、贴图、OCR 和翻译，并在不需要时仅以系统托盘形式驻留。

架构优先级如下：

1. 不使用 Electron、浏览器运行时或大型 UI 框架。
2. 常驻时只保留必要的托盘、热键和配置服务。
3. 截图、编辑、OCR 和贴图由独立模块承载，任何一个失败不能导致常驻主进程退出。
4. 所有涉及系统快捷键、开机启动和外部翻译服务的操作都必须有可见状态和可恢复路径。

不在首版承诺的能力：

- 通用改写第三方应用的快捷键配置。
- 所有应用都可靠支持的自动长截图。
- 不经用户配置即上传截图或文字到网络服务。

## 2. 技术决策

| 领域 | 决策 | 原因 |
| --- | --- | --- |
| 运行时 | .NET 8，Windows 专用目标框架 | 原生 Windows API 和部署支持成熟，资源占用低于 Web 容器方案。 |
| 界面 | WPF | 支持透明无边框截图遮罩、独立置顶窗口、数据绑定和高 DPI 布局。 |
| 系统能力 | Win32 P/Invoke，优先使用 LibraryImport | 全局热键、虚拟桌面、窗口置顶、启动项和截图需要直接调用 Windows API。 |
| 托盘 | System.Windows.Forms.NotifyIcon | .NET 自带，不引入额外 UI 依赖。 |
| OCR | Windows.Media.Ocr | 优先离线处理，语言依赖系统已安装的 OCR 语言包。 |
| 翻译 | ITranslationProvider 抽象 | 通过用户配置的服务实现，避免锁定单一供应商。 |
| 配置 | 安装版与便携版都使用程序旁的 `ScreenshotData` | 安装器为数据目录配置写权限，写入采用临时文件替换避免损坏。 |
| 诊断 | 程序旁的 `ScreenshotData\\Diagnostics` | 仅记录长截图拼接诊断，不记录 OCR 或翻译文本；最多保留 20 份事件日志。 |

外部包控制原则：

- 首版不引入 UI 控件库、DI 容器或日志框架。
- OCR 所需 Windows Runtime 合约包仅在实现 OCR 阶段引入。
- 测试项目使用 xUnit 和 Microsoft.NET.Test.Sdk；生产项目保持最小依赖。

## 3. 解决方案结构

阶段 1 创建下列工程和目录：

    Screenshot.sln
    src/Screenshot.App
    tests/Screenshot.App.Tests
    docs

Screenshot.App 内的职责划分：

| 模块 | 职责 | 不负责的内容 |
| --- | --- | --- |
| Core | 配置模型、快捷键模型、领域接口、结果类型、应用常量 | Win32 调用、WPF 控件和网络访问。 |
| Infrastructure | 配置读写、Win32 封装、启动项、系统托盘、热键注册、日志 | 具体截图交互和编辑器状态。 |
| Capture | 虚拟桌面坐标、截图像素获取、区域选择遮罩、长截图服务接口 | 图片编辑和翻译界面。 |
| Editor | 编辑文档、绘制对象、撤销/重做命令、导出图像 | 捕获屏幕和系统托盘。 |
| Pin | 置顶图片窗口、缩放、透明度、拖动和关闭 | 原始截图的持久化策略。 |
| Text | OCR 服务、语言枚举、翻译服务接口与响应状态 | 翻译供应商密钥的明文硬编码。 |
| Presentation | 设置页、截图后工具栏、编辑器窗口、错误提示和主题资源 | 业务规则和 P/Invoke 声明。 |

初期采用一个 WPF 应用进程。UI 线程仅负责窗口、输入和绘制；截图编码、OCR、翻译、文件写入和长截图拼接在后台任务中执行。任何后台结果回到 UI 时必须检查窗口和取消令牌仍然有效。

## 4. 核心运行流程

### 启动与后台常驻

1. App 启动时载入配置和日志服务。
2. 创建托盘图标和全局快捷键管理器。
3. 主设置窗口默认不在任务栏显示；用户从托盘或快捷键打开它。
4. 关闭设置窗口时按用户配置最小化到后台或彻底退出；托盘“退出”始终释放热键、托盘图标和所有贴图窗口后终止程序。

### 截图

1. 热键管理器发出截图请求。
2. Capture 服务读取当前虚拟桌面和每块显示器的 DPI 信息。
3. 每个显示器显示一个透明选择遮罩，统一转换为物理像素坐标。
4. 用户拖动选择区域，Esc 取消，确认后在后台拷贝屏幕像素。
5. 结果交给后处理工具栏，可复制、保存、编辑、重新框选、OCR 或钉图。

### 快捷键

1. 用户在设置页录入组合键。
2. 规则层先拒绝空组合键、仅修饰键和已知系统保留组合键。
3. HotKeyManager 调用 RegisterHotKey 尝试注册。
4. 注册失败时显示“被系统或其他应用占用”，不覆盖系统快捷键。
5. 不尝试通用修改第三方程序配置；已知应用的适配必须是独立、显式授权的功能。

### 配置写入

1. 设置页生成经过验证的 AppSettings 快照。
2. SettingsStore 先写入同目录临时文件。
3. 写入成功后原子替换原文件；失败时保留旧配置并向界面返回错误。
4. 密钥类设置不写入日志；后续接入凭据保护 API 时迁移敏感字段。

## 5. 配置模型

初始 AppSettings 至少包含：

| 分组 | 字段 |
| --- | --- |
| General | SaveDirectory、ShowTaskbarIcon、LaunchAtStartup、Theme |
| Capture | RegionCaptureHotKey、ScrollCaptureHotKey、OcrHotKey、PinHotKey、OpenSettingsHotKey、DefaultSaveFormat |
| Editor | DefaultFontSize、DefaultStrokeColor、DefaultStrokeWidth |
| Text | OcrLanguageTag、TranslationProvider、TranslationEndpoint、TranslationTargetLanguage |
| Privacy | KeepHistory、HistoryLimit、SendTextToOnlineTranslation |

翻译 API Key 不进入普通 JSON 配置和日志。首版可只支持由用户自行提供的无密钥端点或在后续阶段使用 Windows 凭据保护机制存储密钥。

## 6. 多显示器与 DPI 策略

- 程序声明 PerMonitorV2 DPI 感知。
- 选择框和截屏源坐标统一使用物理像素。
- 遮罩窗口按显示器创建，避免跨越负坐标或不同缩放比例时产生偏移。
- 编辑器和设置页使用 WPF 逻辑像素，由显示器 DPI 自动缩放。
- 阶段 5 的人工验收至少覆盖主显示器、负坐标副显示器和 125% 缩放显示器。

## 7. 高风险功能的实现边界

| 功能 | 首版实现 | 失败或不支持时的处理 |
| --- | --- | --- |
| 长截图 | 先以可识别滚动容器的分段捕获和重叠区域检测为目标。 | 提示该窗口不支持长截图，并保留普通截图入口。 |
| OCR | 使用系统 OCR 引擎和已安装语言包。 | 明确提示缺少语言包或识别失败，不上传图片。 |
| 翻译 | OCR 文本经用户确认后发送到配置的服务。 | 显示服务不可用或配置无效，不影响本地 OCR 结果。 |
| 贴图 | 单独的 Topmost 无边框窗口。 | 单个贴图失败不会关闭主程序；关闭程序时统一释放。 |
| 快捷键 | RegisterHotKey 注册。 | 拒绝系统保留键；占用来源不可判断时要求用户换键或手动释放。 |

## 8. 质量与验证策略

- 单元测试：配置校验、快捷键解析/保留键规则、撤销栈和编辑命令。
- 集成验证：启动、托盘、热键注册、设置持久化和截图主链路。
- 人工验证：多显示器、混合 DPI、关闭设置窗口后的后台常驻、异常退出后的资源释放。
- 构建要求：每个大阶段完成后必须执行 restore、build、test；没有 SDK 时记录为环境阻塞，不把阶段标记为已完成。

## 9. 安全与隐私

- 截图只在内存中处理，除非用户主动保存、复制、钉图或启用历史记录。
- OCR 默认本地执行。
- 在线翻译前须由用户在设置页明确启用，并显示服务名称。
- 日志不得写入截图像素、OCR 原文、翻译内容或凭据。
