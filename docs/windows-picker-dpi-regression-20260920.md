# Windows 4.1.7 高缩放取色残留回归

2026-09-20，仅 Windows，沿用 4.1.7。用户明确确认同一台电脑上 4.1.5 正常、4.1.7 后较高概率出现取色移动残留和框选边框不明显。反馈机器为 Ryzen 7 9800X3D、RTX 5070 Ti、3840×2160 / 160 Hz；显示缩放、HDR 与驱动版本尚未确认。

## 已确认的缺陷

对比本地标签 `v4.1.5` 与 `v4.1.7`，4.1.7 将取色面板从 `FillRect` / 内侧 `FrameRect` 改为 `RoundRect`，画笔宽度随 DPI 增长；局部重绘仍只使用面板布局矩形。宽画笔会绘制到布局边界之外，旧描边未完整恢复，新描边也会被局部裁剪。100% 下的移动测试不能覆盖这个问题。

将既有“连续局部重绘与全新完整帧像素相同”回归扩展为 100%、125%、150%、175%、200%、250%、300%：修复前 100%、125% 通过，其余 5 档失败。失败记录在 `artifacts/windows-selection-shift-20260920/dpi-regression-before.log`。

`ResidentSelectionRenderer.GetDamage` 现对展开的取色面板计入画笔外扩范围，旧位置和新位置同时处理，最终与截图表面相交。布局尺寸、颜色、取色采样、光标输入、显示刷新率及框选行为保持不变；没有改为整屏持续重画，也没有增加常驻资源。之前的绘制失败检查保留。

## 验证范围

- 7 档缩放的连续移动像素回归全部通过；包含展开取色面板到紧凑框选尺寸标签的切换。
- 3840×2160 离屏测试覆盖 125%、150%、175%、200%，负坐标原点、屏幕边缘取色、移动、拖动扩大和缩小选区。每次仅复制实际失效区域到第二张模拟呈现表面，与完整新帧逐像素比较，并检查四边颜色和原截图像素不变。
- 相关 Release 回归 49 通过，6 项真实桌面集成测试按项目约定跳过。修复后绘制专项 21 通过与上述有重叠，不累加。
- 没有向用户桌面显示测试图案、注入全局输入或修改刷新率；本机离屏复现不代表已验证目标机 160 Hz / HDR / NVIDIA 驱动。可以确认一个由 4.1.7 改动引入的高 DPI 残留缺陷，但不能据此声称视频中边框消失等所有现象均已解决。
