# Windows 表格识别与数字快捷键验证（2026-09-17）

## 修改内容

- 表格结构识别补齐缺失的左右外边界，依据实际线段端点推断边界，避免把表格外标题误算成数据行。
- 合并单元格采用矩形分区，保留内部有效分隔线，避免缺线连通区域绕过边界误合并；短分隔线的检测不再随整张表格高度提高门槛。
- 补充三线表、无竖线表格的列间空隙和正文行识别。
- 按已识别的单元格边界裁切、避开表格线，分批使用现有 OCR 工作进程补识别，恢复缺失文字；不改变模型、精度和空闲退出策略。
- 表格结构分析与补识别在后台运行，保留取消与关闭窗口后的结果丢弃。
- 工具栏快捷键支持数字及 Ctrl / Alt / Shift 与数字组合，统一普通截图、钉图编辑和录屏工具栏的匹配逻辑；数字区和小键盘数字采用相同规则。
- 修复输入法迟到的文本事件覆盖已捕获物理组合键的问题，扩大设置输入框以显示组合键。

## 验证结果

- Windows 全量回归：1857 项通过、102 项按桌面或外部依赖环境规则跳过、0 项失败。此轮在最终“表格外标题”边界修正之前执行。
- 最终 Release 编译及相关回归：120 项通过、0 项跳过、0 项失败。覆盖最终边界修正、合并表头、纵向合并、55 行长表中的短表头线、三线表、缺失侧边框、中文补识别、快捷键设置往返保存及准确匹配。
- Ctrl+1 同时验证设置捕获结果与全局识别快捷键配置验证；数字组合键的工具栏分发验证覆盖精确修饰键匹配。
- 实际原生 OCR 使用本机已安装的 PP-OCRv6-Small，离屏生成 700×270 中文表格，包含缺失的左右边线和合并表头。两次完整识别为 820 ms、432 ms，输出文字及 HTML 合并单元格断言均通过。
- OCR 工作进程记录的峰值总工作集为 213.1 MiB，采样时专用提交量为 167.7 MiB；已确认空闲期限后进程实际退出。这些数值不是主程序空闲内存。
- 验证取消后可再次识别、OCR 工作进程退出后可重新加载，以及大小两种图像预算下的分批处理和资源释放。

实际 OCR 样本输出（首行第二格属于合并表头）：

```text

项目	状态	120	王明
安装	已完成	240	李华
检查	正常	360	张强
```

耗时和内存是本机该样本的测量值；用户报告的失败表格原图尚未提供，尚未按其实际样本逐格核对。不将生成样本的通过率推广为所有复杂表格的准确率。
