# Windows 剪贴板与 PP-OCRv6 排查（2026-09-18）

本次只改 Windows 复制服务、钉图复制、OCR 错误处理及相关验证。没有修改 macOS、长截图算法、模型、识别分辨率或版本号；没有发布或推送。

## 已确认与未确认

- 用户反馈：白云歌在空白处转录后复制失败，SnapCut 后台运行时出现，退出后恢复。这个关联尚未在本机完整复现，不能宣称已经修复该用户的全部问题。
- 当前 SnapCut 源码没有剪贴板后台监听或轮询。旧钉图、视频复制仍有 WPF 同步调用；图片原生写入还使用空 HWND。统一为后台串行原生写入，预先构造数据，使用临时消息窗口，写入后立即 CloseClipboard、销毁窗口；失败、取消均释放资源。钉图复制失败明确提示，关闭后不回写界面。
- 提供的 OCR 日志明确显示 RapidOcrNet.TextClassifier.Dispose 的空引用覆盖了初始化错误。已保留原始异常和调用栈，将清理错误单独记入错误诊断；识别最终失败后结束工作进程。旧日志无法恢复最初错误，不能据此断言旧 CPU、内存或模型损坏。

## 白云歌源码分析

分析的是公开仓库提交 `71a91bf4e9e31277074f9322cd029934a27fc409`，不代表反馈者安装版本一定相同。

- 输入框路径优先模拟键入；桌面等不可编辑目标走剪贴板，因此两种场景表现不同符合其实现。
- 每次复制新建 STA 线程，调用 WPF Clipboard.SetText；最多两次尝试，每次等待约一秒。任何异常与等待超时均返回失败，未记录异常或持锁进程。“剪贴板被占用”是统一提示，不能定位到独占锁申请的具体阶段。
- 等待超时不会取消原线程，重试可能与迟到写入并存；输出从 UI 上下文调用，Thread.Join 还会同步阻塞 UI。改进方向是保留原始异常/持锁进程，串行执行可取消的复制，避免超时后留下写入线程。

依据：[复制实现](https://github.com/bilibilibaiyun/BaiYunGe/blob/71a91bf4e9e31277074f9322cd029934a27fc409/src/BaiYunGe/Core/Output/TextOutputService.cs#L94-L144)、[UI 调用](https://github.com/bilibilibaiyun/BaiYunGe/blob/71a91bf4e9e31277074f9322cd029934a27fc409/src/BaiYunGe/Core/RecognitionPipeline.cs#L567-L587)、[统一提示](https://github.com/bilibilibaiyun/BaiYunGe/blob/71a91bf4e9e31277074f9322cd029934a27fc409/src/BaiYunGe/UI/LocalizedText.cs#L97)。未修改该仓库或运行其 ASR 模型。

## 验证证据

- Release 编译成功。新修改没有新增编译警告；工作区原有分析器警告未在本任务处理。
- 相关 OCR、像素传输、表格、钉图组合及剪贴板回归最终分别通过，共 34 个不同用例。11 个依赖真实桌面窗口的钉图测试按约定跳过。
- 真实 PPv6：首次约 390 ms、连续约 66 ms、重新加载约 331 ms；同图结果一致，工作进程空闲约 10 秒实际退出，主测试进程当时未加载 ONNX。取消、损坏模型失败后进程退出及再次识别恢复均通过。仅为本机样本，不代表旧电脑速度。
- 剪贴板测试覆盖 Unicode、HTML、图片像素顺序、文件拖放格式、混合写入顺序、真实占用重试、取消和写入异常后的释放、其他线程独占打开及临时所有者销毁后的数据可读性。
- 独立 PowerShell 进程对照（与剪贴板回归分开执行）：SnapCut 退出时 10 秒内 318/318 次独占打开成功；最新 Release 后台运行时 20 秒内 635/635 次成功。均不读取或修改剪贴板内容。这只能排除本次环境和时段的持续持锁。
- 临时模拟白云歌的 STA / WPF SetText / 一秒 Join 路径：SnapCut 退出与后台运行两种状态，各用现有剪贴板、SnapCut 原生文字、SnapCut 原生图片作为前置内容，均在 Clipboard.Flush 抛出 `COMException 0x800401D0`，约 990–1021 ms；部分超过外层一秒等待。这是本机兼容性复现，不能归因为反馈者同一故障，也不能当作白云歌整套语音流程验证。
- 本机回归期间曾记录 GameViewer 短暂持锁；测试读回使用有限重试，不将第三方瞬时占用误判为 SnapCut 未释放。没有关闭或修改该软件。

## 故障现场取证

运行 `tools/Probe-ClipboardLock.ps1 -Seconds 30 -OutputPath clipboard-lock.json` 后，在这 30 秒内复现转录失败。默认只记录实际持锁窗口、PID 和进程信息，不打开、不读取、不写入剪贴板内容；结束后不留后台任务。输出中的 OwnerPid 是内容所有者，LockPid 才是持锁窗口所属进程；空 HWND 锁可能无法识别 PID。

`-TestExclusiveAccess` 用于单独进行短时独占申请对照，不应与转录或其他剪贴板测试同时运行。脚本不是正式程序中的常驻监控。

仍需反馈电脑使用的两款软件版本、故障时持锁记录，以及修复版产生的新 OCR 错误日志，才能进一步确认其特定兼容性原因。
