# Windows 按硬件分配识别和翻译资源

继续使用 4.1.7-localtest，同名测试包覆盖，不发布正式更新。只修改 Windows；Medium、TranslateGemma 4B、语言、提供方顺序和识别阈值保持不变。

## 实现

- 仅在计算工作进程按需启动时读取 CPU 物理核心、性能核、标称频率、AVX2、可用内存，并做一次 64 ms CPU 负载采样。采样在计算线程进行，不在界面／输入钩子中进行；没有开机跑分或待机轮询。读取失败采用保守预算，未知内存不等同于零内存。
- Medium OCR 使用同一预算准备及推理。本机 8 性能核＋16 效率核、内存充足时允许 12 线程；低频、较少核心、内存紧张和系统繁忙时降低预算。每个短暂复用的 OCR 工作进程固定预算，退出后再次加载重新采样；并非在一次推理中持续重建线程池。
- OCR 检测、方向和识别会话的空闲线程不再忙等待。相同图片验证关闭忙等待后文字结果一致，12 线程原始引擎耗时约 4.72／4.71 秒；没有靠持续占用 CPU 换取表面响应速度。
- 离线大模型保留已有 Vulkan 显卡、混合及 CPU 回退路径，加入模型、上下文、桌面显存余量和待译任务数约束。显存紧张及集成显卡保持少量并发；高余量独显最多 8 路。本机整页 4／8／12／16 路比较中，8 路已经接近最佳，12／16 路没有明显收益。
- TranslateGemma 的 CPU 推理不再统一限制为 4 线程，生成和正文预处理分别分配；GPU 模式保持较小的 CPU 提交线程池。实际运行方式、线程数和并发显示在翻译状态中。CPU／GPU 探测及进程创建不阻塞界面线程。
- 只为“已最小化启动”提示而创建完整 WPF 功能进程的路径，改为带主题颜色的轻量原生提示，约 1.5 秒销毁。保持不激活、不抢鼠标、无任务栏按钮。用户要求启动设置或恢复钉图时仍执行对应功能。
- 模型仍按需加载，连续操作短暂复用，空闲约 10 秒结束原生工作进程；取消、失败和主程序退出时释放。没有清空工作集、常驻模型或降低图片分辨率来制造指标。

## 实测

测试机：Intel Core Ultra 7 270K Plus，24 个逻辑／物理核心（8 性能核、16 效率核），64 GB RAM，RTX 5070 Ti 16 GB。均为单机样本，不是所有硬件的性能保证。

用户 1658×1115 网页图，完整 OCR → 段落整理 → TranslateGemma 翻译：

| 项目 | 修改前 | 修改后 |
| --- | ---: | ---: |
| Medium OCR 冷路径 | 6.82 秒 | 5.32 秒 |
| 翻译首次（包含模型启动） | 6.85 秒 | 7.00 秒 |
| 翻译连续 | 4.45 秒 | 4.36 秒 |

OCR 的 67 个段落逐项一致。翻译保留同语言／无需翻译过滤、完整性校验和仅补译失败段落；首轮处理 50 个片段，自动补译 1 个片段后全部完成。没有用返回原文充当翻译成功。此次没有证据表明高配独显的整页翻译明显提速，首次加载仍约 2.6 秒。

原始 Medium 引擎相同网页的 8／12／16／20 线程分别约 6.33／4.61／4.50／4.81 秒，98 个文字块一致，选择 12 线程兼顾余量。Small 8 线程原始引擎约 1.6 秒，因此仍不能承诺 Medium 达到 Small 的速度。当前 OCR 执行后端仍是 CPU，GPU 用于离线翻译。

620×110 中英文样本：OCR 冷 563 ms、连续 122 ms、空闲后重载 558 ms；主动框选准备 349 ms、准备后首图 222 ms。子进程总工作集／峰值总工作集约 298.4 MiB，专用提交约 264.0 MiB，父进程未加载 ONNX。没有将总工作集当成专用工作集。

TranslateGemma 4B 短句验证：GPU 首次约 2.49 秒、连续 104 ms；强制 CPU 路径首次约 2.68 秒、连续 777 ms。Hy-MT2 同样覆盖 CPU／GPU。四种组合均验证取消后恢复、空闲约 10.2 秒实际退出、再次加载和故障退出；这些短句数据不能代替整页耗时。

另一次独立的整页资源观察中，OCR 子进程峰值总工作集约 1,009 MiB，观察到的最大专用提交约 1,352 MiB；翻译子进程分别约 1,685 MiB／6,949 MiB。显卡全机总已用显存采样从 2,455 MiB 到最高 8,382 MiB（总量 16,303 MiB），保留约 7.7 GiB 余量。显存数字包括桌面及其他应用，不能当成 SnapCut 独占显存；专用提交不等于实际驻留内存。资源观察包含额外采样开销，不用于上表耗时比较。证据为 `memory-samples.json`。

## 回归与边界

- 资源预算覆盖较少／较多物理核心、相同逻辑核的不同拓扑、低频、无 AVX2、低内存、高负载、探测失败、集显，以及 4 GB 独显余量足够／紧张的可控输入。没有假称这些是各档真实电脑跑分。
- 设置提示已说明用途、预算、按需加载和空闲释放；原生启动提示按 100%／150%／200% DPI 离屏验证。
- 相关功能回归 100 通过，3 个真实剪贴板用例默认跳过；首次失败是旧测试仍断言 Small 文件大小，已按已固定的 Medium 文件总大小 139,842,893 字节修正。独立 OCR 工作进程 7 项通过，离线模型 CPU／GPU 生命周期 4 项通过。
- 未在反馈者电脑实测鼠标卡顿；移除了已确认的多余进程启动与输入交接，仍需用户拿测试包确认实际感受。没有更改 macOS 或长截图算法。

证据位于 `artifacts/windows-page-performance-20260918`：`baseline.json`、`adaptive-final.json`、`ocr-thread-probe.log`、`ocr-spin-probe.log`、`slots-*.json`、`resource-budgets.trx`、`windows-regression-final.trx`、`ocr-lifecycle.trx`、`translation-lifecycle.trx`。最终包大小、校验和及打包回归见 `docs/releases/4.1.7-localtest-validation.md`。
