## 视频观察

用户提供的 SnapCut-20260918-205845.mp4 为 2048×1200、24 fps、310 帧。选区最后一次几何变化在第 206 帧（8.583 秒），工具栏从第 216 帧（9.000 秒）可见，两者相隔约 0.417 秒。录像没有精确的物理鼠标松键时间，不能把此差值当作完整的鼠标松键延迟。画面展示远程桌面中的此前测试包，不能仅凭远程画面认定网络是原因。

仅本地读取视频并抽帧分析，未上传；用户原始视频保留。帧号和像素统计留在 artifacts/toolbar-video-20260918/video-timing.json。

## 确认的缺陷与修复

FeatureProcessWorker.PrepareAsync 读取完整 bootstrap 后只保存 Settings；ConnectAsync 再构造仅有设置的新消息，把 Flag 和 HotKey 丢掉。App.FeatureProcesses 中依靠这两个字段执行的早期截图／录屏工具栏准备被跳过，却仍向宿主报告 ready。

现直接保留并传递完整 bootstrap，准备真正完成后才报告 ready。宿主已有的首帧与激活屏障保持不变，仍只在用户触发框选时启动工作进程。后续 prepare-capture-toolbar 消息继续幂等处理；没有常驻窗口、模型预加载、强制清空工作集或新增长期轮询。

此前 0.24～0.30 秒的“启动加隐藏工具栏准备”说法不成立：旧测试只检查无可见窗口，无法证明隐藏窗口已经创建。新测试直接枚举工作进程的准确窗口标题和 PID，检查 ready 时窗口存在且隐藏，并检查交接后是同一个 HWND。修复前四项测试全部因窗口不存在失败，修复后通过。

## 实际验证

本轮 29 项相关回归全部通过，包括明确启用的真实桌面呈现测试；使用冻结的实际桌面，无全屏测试图案、无全局输入注入。录屏测试只打开和取消准备工具栏，不启动采集或录制。

| 路径 | 未准备时命令到呈现确认 | 已准备时命令到呈现确认 |
| --- | ---: | ---: |
| 截图 | 362.6 ms | 148.5 ms |
| 录屏 | 249.7 ms | 152.3 ms |

这是同一修复构建两条路径的本机对比，不是用户电脑前后对比；早期独立一轮截图测得 315.2／132.8 ms，显示存在运行波动。计时从发送最终选区命令到收到实际交接确认，不含冷工作进程创建和用户拖动时间；准备路径模拟了 350 ms 框选时间。极短拖动仍可能等待准备结束。

- 本机 Core Ultra 7 270K Plus / 64 GB / RTX 5070 Ti。2／8 逻辑处理器亲和性预算下，真实进程启动加隐藏窗口创建：截图 492／510 ms，录屏 453／382 ms。此预算不模拟 4800H 单核速度、磁盘和 GPU 负载，不能保证另一台电脑同样耗时。
- 截图与遮罩交接的冷／连续像素采样，RGB 通道最大变化为 2，低于允许阈值 4；选区获得输入。未移除防闪屏屏障。
- 已准备截图工作进程总工作集约 234 MiB、峰值约 248 MiB、专用提交约 182 MiB；录屏约 177／177／104 MiB。这些是任务期间数值，不是后台驻留内存，也不是专用工作集。
- 四个真实窗口用例关闭后工作进程均在约 2.1～2.2 秒退出；取消准备、迟到像素、设置保留及原始 BGRA 传输另有回归。
- 初次补充录屏测试错误地把 NativeSelectionId=0 的通用隐藏确认当作最终工具栏确认，导致 2 项断言失败。测试协议修正为先回应该消息、再等待选择编号 93 后，29 项全通过；不是修复产品错误后掩盖失败。
