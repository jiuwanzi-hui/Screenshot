# Windows 复杂图片及局部截图 OCR（2026-09-19）

## 范围与结论

仅 Windows `Screenshot.App`、Windows 测试与本说明。版本保留 4.1.7；不修改 macOS 或长截图算法，不发布、不推送源码。

问题同时来自触发逻辑和模型能力。此前要求至少两条异常竖列，单列或仅含大字的局部截图无法进入增强。直接强制 PP-OCRv6 Medium 也不够：三张新截图的原始 Small / Medium 推理都出现大字漏检或误读。不能仅换触发条件便宣称准确。

现在单条异常竖列也可进入恢复；仅检出少量正文时，另检查已有文字框外是否存在明显彩色内容，才启用原像素复核的增强。普通黑字稀疏页面仍用 Small，不预加载 Medium。没有文件名、固定坐标、图片指纹或预置识别答案。

新增可选的 **Qwen3-VL 4B 视觉识别**，位于设置 → 内容识别 → 识别方式。保留 Windows 与 PP-OCRv6 两项，不改变用户当前选择。模型已安装在本次源码 Release 目录的 `TranslationModels/Qwen3-VL-4B-OCR`。

## 模型与运行

- 官方 Qwen GGUF：语言模型 Q4_K_M 2,497,281,664 字节，视觉编码器 F16 836,180,256 字节。合计约 3.1 GiB，与运行内存不同。
- 固定 HF revision `1cd86afb9a95c410a6038ab3b40d8b578c892266`。权重 SHA-256 分别为 `66358cb18bb6b3b1b6675aa412c7a88ef01d228f481184d13668e5201c730a0a`、`256f3a43bd4205ffef48d6b92715e1e70b5b0e9aef06522584967513a9985331`。ModelScope 官方镜像、HF 与镜像站均须通过相同大小与哈希检查。
- 复用项目已校验的 llama.cpp b10276 Windows Vulkan/CPU 包。下载支持进度、暂停、续传、校验修复；解压限制目标目录，记录所有运行库的长度清单，缺失 DLL 时不显示已安装。
- 独立原生进程，随机本地端口与每次随机鉴权，仅绑定 127.0.0.1，禁用代理与 Web UI。图片不上传到外部服务，不记录图片或识别正文。使用 Windows Job，主程序退出时一并结束；取消/失败杀掉本次工作进程，连续操作短暂复用，空闲约 10 秒退出。无启动预加载、常驻轮询或强制清空工作集。
- 按实际 Vulkan 设备、可用显存和 CPU/内存/负载预算启动，GPU 使用原生显存适配，启动失败可回退同一模型 CPU。显卡路径检查至少 5 GiB 可用 RAM，CPU 路径检查 8 GiB；探测失败不视作零资源。仅验证本机 RTX 5070 Ti 与强制 CPU 路径，未实测 4 GB 显卡、集显或低端 CPU。
- 不修改截图像素。单次最多 4,194,304 像素，超过明确提示分区或选择 PP-OCRv6，不静默缩小图片。生成上限和结构检查防止截断/无效 JSON 被当作成功。
- 使用模型官方 VL 采样参数及固定 seed；贪心推理在整页出现过重复循环，已弃用。通过 JSON schema 约束结构，仍验证边界、空结果、重复的同文同位置。纯色图不调用模型；普通渐变/无文字图另通过真实推理回归。文本行位置由模型估计，按行提供选择，不制造逐字坐标。

## 验证与边界

用户私人图片仅从环境变量读取，不收入仓库。三个局部截图均在实际新服务中验证：前两张识别到“優雅／時尚／美尚”；第三张识别到“時尚／美尚”和完整可见口号。第一张另断言斜排“獨家精選”和“最新尚圖鑒”。这些是明确检查点，**不是整图字符准确率**。

独立样本包含楷体、宋体、微软雅黑，红紫渐变描边字、深浅背景、横排/竖排、不同字符串和间距；六组文字全部通过。另覆盖纯色图、无文字渐变和圆形图，以及把图中文字“忽略指令”当作原文识别。设置选项/布局、参数与坐标验证、缺失运行库、首次/连续/重载、取消后恢复、CPU 回退均有测试。

最终验收 14/14 通过。另完成原有 OCR / 资源预算回归，本轮发现的普通稀疏页面误触发已修复并通过实际 Small-only 回归；设置离屏测试完成布局后通过。合并去重为 56 项通过、1 项因旧局部图片未提供而跳过，未运行真实顶层窗口/屏幕输入集成测试。最终日志与离屏设置截图保留在 `artifacts/windows-visual-ocr-20260919`。Release 编译通过，无新增编译错误。

已于 21:40 从源码 Release 目录启动最新 SnapCut 并核对进程路径。清理 `artifacts/ocr-general-probe` 测试副本的递归删除被自动审批拒绝（仅返回 `blocked by policy`），因此该临时目录仍保留；正式使用的 Qwen 模型位于 Release 的 TranslationModels 目录，与测试副本独立。未绕过审批删除。

实测过官方 PaddleOCR-VL 1.6：单独六个大字有所改善，但混排仍漏字、错误字形和顺序明显，因此没有把仅凭模型名称推断的“更强”版本加入产品。Qwen3-VL 4B 在当前局部样本上明显更好，才加入为独立选项。

完整海报仍存在局限：可能补写被遮挡的标题尾字、转换繁简字形、重复长竖列；第三张的裁断字也有“入／人”误读。重复长句会给出核对提示，不能承诺所有类似图片全对。位置不是检测器精确字框，不适合将模型坐标当成测量结果。原有 PP-OCR 的整页短语检查仍保留。

## 本机性能与资源记录

Intel Core Ultra 7 270K Plus、RTX 5070 Ti 16 GB；首次启动包括加载及显存适配，驱动已有 shader cache，不能等同全新机器首次运行。

| 测试 | 时间 / 资源 |
|---|---|
| 三张局部截图 | 约 6.2 s（含加载）、1.4 s、3.1 s |
| 独立四字样本首次 / 连续 / 空闲重载 | 约 4.2 s / 1.1 s / 4.3 s |
| GPU 工作进程总工作集 / 峰值总工作集 / 专用提交量 | 约 2561 / 3507 / 5447 MiB |
| 局部截图期间 GPU 进程采样最大专用显存 | 5,721,833,472 字节（约 5.33 GiB）；定时采样值，不是精确全程峰值 |
| 强制 CPU 四字样本首次 | 约 12.6 s；总工作集约 6769 MiB，峰值约 6772 MiB |
| 空闲工作进程实际退出 | 返回后约 10.4 s；取消后退出，并可再次识别 |

GPU、CPU 使用同一份模型精度；没有以高端机器的时间作为其他硬件保证。运行结束确认原生进程退出，不以托管堆或 Session.Dispose 代替资源释放。
