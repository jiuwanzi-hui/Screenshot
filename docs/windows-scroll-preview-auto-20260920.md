# Windows 长截图预览遮挡与自动恢复修复（2026-09-20）

本轮只修改 Windows。手动模式的拼接、输入节奏、合并算法未修改；手动与自动共用的像素采集修复。预览窗放置、尺寸、显示状态及边框放置逻辑不变。

## 黑色右边的原因与处理

旧采集先读取屏幕，再通过 `GetDC(HWND)` / `BitBlt` 补回预览窗和边框遮住的区域。对硬件合成窗口，调用成功不表示读到了被遮挡的真实像素，窗口 DC 可以返回黑色；这些黑块会随每次新增条带拼进结果，与用户宽选区截图中的右侧条纹一致。

新增 `ScrollCaptureFrameSource`：每次长截图按需建立一个目标窗口的 Windows Graphics Capture 会话，复用现有 `RealtimeCaptureSource`，直接取得完整窗口合成表面，再按原选区坐标裁切。预览遮挡部分与可见部分来自同一帧。不移动、隐藏或逐帧切换预览／边框的捕获亲和性，不改变其他窗口层级。

系统支持并允许时，在会话创建时请求不显示系统捕获提示边框；不弹权限请求，也不绕过系统决定。SnapCut 的选区边框保持原样。

选区超出窗口时，只对窗口内使用实时表面，外部仍保留屏幕像素；固定边框外侧用开始截图时的背景恢复，窗口内部始终由实时表面覆盖。若预览遮挡部分超出目标窗口，拒绝使用不完整画面，不拿黑色或旧窗口 DC 冒充内容。

会话只在当前长截图期间存在；帧池容量为 2，未更新时仅复用当前会话最后的完整帧，首帧等待有上限并可取消。采集和释放串行，在后台完成；完成、取消或失败离开会话作用域后释放帧、缓冲与采集设备。

## 自动模式

- 增加分布式内容匹配通道，按重叠正文逐像素校验，保留现有 2 级像素差容差并避开右侧滚动条，减少宽页面空白边距对近似匹配的影响。只有重叠内容通过校验、移动量和方向允许、历史边界验证通过时才使用；其余情况继续原有近似搜索。保留最小新增行数、移动上限及边界保护。
- 原来的失配恢复次数会在重新找到旧视口时清零，即使没有新增内容也会重新获得回滚次数，因此可以反复上下滚动。
- 新恢复预算按已保存图片高度推进恢复，新增不足 24 行不补充预算；最多两轮自动恢复。无法继续时暂停并保留已有结果，用户主动继续可重新获得有限恢复机会。实际能够补回的跨视口跳跃仍可恢复，不将所有失配直接视为到达边界。

CPU 占用不能单独代表拼接效率。失配时的等待、重新取帧和反向滚动会增加时间而不增加 CPU 忙碌比例。本次降低无效搜索和恢复循环，没有盲目增加线程，也没有降低采集分辨率。

## 验证

- Release 长截图、自动／手动、上下往返、固定栏、小选区、快滚、重复文字、取消、预览与相关窗口回归：392 通过，15 个依赖真实桌面的测试默认跳过。
- 单独启用 `ScrollCaptureFrameSourceTests`：4 通过，包含真实 WPF 合成窗口被实际预览窗与原生边框遮挡时的逐像素对比、内容更新、位置保持、外部边界、取消与释放。
- 新服务级回归模拟“向前失配，回滚又只找到旧画面”：能在有限恢复后暂停，保存结果像素不变。另有固定栏／无固定栏的可恢复跳跃测试，确认仍能续接完整正文。
- 用户长图的右侧已含黑块，不能直接作为干净源图。回放仅取其未损坏的左侧 2050 像素作为测试数据，原附件未修改；按不同步长生成 75 帧，最终 2050×5337 全图逐像素一致。优化后一次本机回放为 1.784 秒；修改前该用例约 5 秒。此为离线算法回放，不能当作真实浏览器滚动端到端耗时。
- 记录：`artifacts/scroll-regression-20260920.log`、`artifacts/scroll-frame-source-final.log`、`artifacts/scroll-recovery-validation.log`。测试素材来自本地附件，通过 `SNAPCUT_SCROLL_SAMPLE` 指定，不随安装包分发。

真实遮挡测试覆盖本机 Windows/WPF 合成表面；用户原 Doubao 浏览器会话、其他显卡／驱动、远程电脑尚需使用临时包验证。没有宣称所有网页动画或完全缺少重叠像素的跳跃都可无损拼接。
