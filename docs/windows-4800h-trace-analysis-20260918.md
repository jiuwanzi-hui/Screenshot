这不是另一条“最终交接确认”事件，不与上表冒充完全相同的测量口径。

本次 ZIP 没有录屏框选样本，不把截图阶段数据当作录屏的目标机证据。

## 焦点问题：本机复现及修复

给现有真实子进程交接回归增加“关闭后 300 ms、子进程尚未退出”的检查。
原实现的两轮普通截图用例均复现：前台 HWND 属于工作进程、IsWindowVisible=False，
窗口类为 WindowsForms10.Window；录屏对照回到原来的可见前台程序。
例如 baseline-focus-class.trx：工作进程 17028 和 1448 的隐藏辅助 HWND 仍持有前台。
子进程约 2.1 秒后退出，才将焦点自然交回。这与用户观察吻合，不是 GC 恢复焦点。

边框、遮罩、尺寸提示原来在 Handle 建好后才写 NOACTIVATE；WinForms 的窗口创建、
句柄重建和样式刷新并不以这次手动写入为持久约束。现在在 CreateParams 中声明
NOACTIVATE、TOOLWINDOW、TRANSPARENT，并使用 ShowWithoutActivation。
修改后的实际交接检查在子进程继续存活时就已恢复其他程序前台。
另加真实 HWND 重建回归，检查创建和重建均不可见、不夺焦点且保留 NOACTIVATE。
没有用延长进程驻留、强制抢回资源管理器或定时反复激活来处理。

## 工具栏准备调整与验证界限

隐藏准备只测量真实工具栏，保留其资源树和测量结果；不再提前布局整屏后把工具栏
折叠，正式显示时重新展开。窗口仍保持隐藏、不激活，采用原来的首帧、防闪交接与取消流程。
补充 XAML 载入、三个原生辅助窗口分别创建、HWND 和边框准备的阶段；限时诊断快照
增加前台 HWND、PID 和可见性，不读取其他窗口标题或输入内容。

本机 2/8 逻辑处理器预算、准备后取消、真实截图／录屏交接、像素防闪和焦点共 14 项通过。
同一源码 Release 的准备后截图交接 171.6 ms，像素交接样本最大通道差 0；
这些结果不是 4800H 上的新包实测，不能声称该机已达到瞬时显示。

另外比较过普通不透明 WPF 窗口和 ReadyToRun 预编译，没有获得足够明确的端到端收益，
均未纳入交付；没有改变画面透明度或扩大安装包来掩盖问题。
ReadyToRun 的用途与尺寸取舍参考
[Microsoft .NET 部署说明](https://learn.microsoft.com/en-us/dotnet/core/deploying/ready-to-run)。
