# Windows 轻量翻译与设置交互验证（2026-09-14）

## 问题及修改

- 用户提供 Ryzen 7 4800H、约 32 GB 内存、GTX 1650 Ti 4 GB 的配置，Hy-MT2 1.8B 加载时显示 CPU 并等待 45 秒。代码中的 `IsLightweight` 分支确实跳过全部显卡探测，固定使用 `--device none -ngl 0`。这能解释未使用显卡，不能据此断言已解释全部 45 秒耗时。
- 轻量模型现在按实际设备和可用显存选择 GPU；资源宽裕时直接加载，紧张时保留原生自动分配，GPU 加载失败时回退 CPU。轻量模型单槽快速加载预算为模型文件大小两倍加 768 MiB；覆盖 3100 MiB 可用显存通过、1800 MiB 不直接全量加载及核显保守路径。预算验证不等于真实 1650 Ti 速度验证。
- CPU 路径已有可用内存检查，不再执行显存分配。显卡探测给较慢机器最多 5 秒；退出错误显示退出码，运行状态保留回退原因。模型、量化精度、语言及提供方顺序不变。
- 设置不再因每次选择而同步创建输出目录、重复注册未变的快捷键、重建同一色板或扫描未改变的历史目录。设置写盘后台合并，内存读取消费最新已接受配置，退出前仍刷新保存；验证了重新打开配置文件读取最终值。
- 普通 TextBox 的 Copy 在后台写入 Unicode 剪贴板，连续请求串行，取消等待不阻塞后续复制。原生剪贴板写入使用有效的隐藏消息窗口作为 owner。HTML 写入中途失败时不释放已经交给系统的 Unicode 内存。失败保留输入文字并反馈；窗口卸载后不再更新其状态。密码框和富文本控件保持自身语义。

## 实测范围

测试机为 Intel Core Ultra 7 270K Plus（24 核 / 24 线程）、RTX 5070 Ti，**不是用户的 4800H / 1650 Ti**。使用已安装的 Hy-MT2-1.8B-Q4_K_M 和随程序分发的 llama.cpp b10276 Vulkan 运行库。

测试发送固定的普通文本，不读取用户的应用 ID、密钥或截图正文。首句为 “Please save the document before closing the window.”，随后验证“打开设置，选择目标语言。”的英译。

| 路径 | 新模型进程加载 | 加载至首句译完 | 连续翻译 |
| --- | ---: | ---: | ---: |
| 强制无显卡探测结果，CPU | 1341 ms | 1781 ms | 392 ms |
| RTX 5070 Ti，GPU | 1688 ms | 1732 ms | 44 ms |

“新进程加载”包含设备探测（GPU 路径）和新工作进程初始化；系统文件缓存可能已存在，不是重启后的磁盘冷读，也不包含 OCR 和截图渲染。单句性能不能推广为表格几十个单元格的总耗时。

两条路径均验证中英互译、取消后重新建立可用会话。GPU 工作进程最后一次任务结束约 30.2 秒后退出；结束任务时其专用提交量约 3585.6 MiB、总工作集约 336.0 MiB，这两项都不是显存。该次使用高显存机器的多槽配置，不代表 4 GB 显卡预算下的占用。

Release 相关设置、复制及真实模型回归：59 项通过，4 项依赖真实桌面布局的测试按默认规则跳过。随后扩展的两条真实模型测试通过，增加了取消重建及 30 秒空闲退出验证。早一组包含设备预算及翻译批量行为的回归为 75 项通过、4 项默认跳过。

实际通过设置快捷键打开了源码 Release 构建；后续窗口自动化遇到前台激活失败，因此未把真实 Ctrl+C 交互时延当成已完成实测。复制忙碌、保序、取消、失败提示及关闭弹窗后的行为通过可控测试验证。
