# Windows：选区边界 OCR 与空闲后工具栏

本轮沿用 4.1.7-localtest，只修改 Windows。用户确认 19:59 包在 Ryzen 7 4800H / 32 GB 电脑上，空闲释放后截图和录屏工具栏都要等一秒多；紧接着再次使用很快。本机没有同等迟延，不能把本机测试替代那台电脑的结果。

## OCR 通用处理

- 原实现按竖排检测框高宽比取整猜字数；选区收紧、字体变窄或字距改变会使猜测差一个字。现在只有原结果不完整或低置信度时，最多检查原猜测及相邻两个字数，仍要求完整 CJK、较高置信度和显著提升。每图最多四列，保留条带尺寸与像素上限，不写入图片内容或答案。
- 窄条小图先识别原尺寸，再最多补一次背景边距；只接受保留原文全部字符顺序、且新增文字的结果。区域和词框移回原始截图并裁剪到图片范围，不修改保存像素。原有有限放大重试保留。
- 同一行按纵向重叠判断，再按横坐标排序，避免字距大时检测框轻微高低差把文字顺序打乱；竖列不混进横行。
- 普通页面继续使用 Small，困难小图按需增强，模型空闲约十秒退出。没有增加常驻模型、降低阈值或修改翻译配置。

验证包含雅黑、宋体、楷体，横／竖排、两档字距、两档边距共 24 个组合，额外 2／6 字布局四个组合；另有真实小字、深浅底彩色字、中英混合、空白、字符坐标、取消及退出回归。新紧选区原图及向内收 2／4 像素时，下方完整字通过检查。原六字图五档缩放与两档边距仍通过。裁掉笔画的字不能保证恢复，末字“鷄／鶏”异体仍可能识别不准确。

## 截图和录屏工具栏

- 冷进程收到设置后，在隐藏状态创建当前操作的工具栏和 HWND，准备可以与驻留进程抓取首帧、用户框选重叠。输入接管和显示仍等待原来的首帧屏障；隐藏准备应用当前主题、语言及标注偏好。
- 截图在框选期间通过仅当前用户可用的管道传送同一份原始像素，在后台构建冻结预览。松手后的命令复用图像，不再传第二份，不重新抓桌面。选择编号隔离迟到帧，取消、替换和退出释放图像。
- 录屏复用预先建立的实际控件树；隐藏准备不创建录制器、不启动摄像头、麦克风、输入监控或计时器。正式会话接入用户录制设置、位置和缩放，失败或取消关闭准备窗口。
- 仅在用户启动框选后准备；空闲仍退出功能进程，没有通过常驻大界面、清空工作集或阻塞 GC 伪造低内存。原有防闪屏交接保留。

## 本轮证据与限制

74 项相关回归通过，4 项真实桌面集成用例按项目约定跳过；最终 UI／表格／页面速度补充回归 34 通过、1 桌面用例跳过，两批部分重叠。隐藏工具栏复用、录屏选项接入、无设备提前启动、像素一致性、迟到帧释放及真实子进程取消退出均有覆盖。

2026-09-18 后续视频排查更正：此前记录的截图 306／244 ms、录屏 244／240 ms 只覆盖进程启动，不能称为“启动加隐藏准备”。工作进程重建 bootstrap 消息时丢失了准备标志和操作类型，原测试只检查无可见窗口，没有确认隐藏窗口实际存在。框选中的后续准备消息仍可工作，但更早的 bootstrap 准备没有生效。该缺陷已修复，新的测试在 ready 时检查实际 HWND，并确认最终复用、显示和释放；新证据见 [视频与工具栏交接](windows-toolbar-video-20260918.md)。

同一张 1658×1115 网页 Small 首次 2.008 秒、连续 1.542 秒，93 个区域，文字一致；前轮 2.074／1.509 秒，基本持平。600×100 混合小选区连续识别 41 ms。OCR 生命周期回归 620×110 首次／连续／重载 408／42／411 ms，原工作进程退出，父进程未加载 ONNX；总工作集约 167 MiB、专用提交约 124 MiB。此处总工作集不能当作专用工作集。

本机硬件为 Core Ultra 7 270K Plus / 64 GB / RTX 5070 Ti，OCR 用 CPU 12 线程。最新包、校验及单独艺术字冷启动数据见 `releases/4.1.7-localtest-validation.md`；原始小体积记录在 `artifacts/general-ocr-cold-ui-20260918`。用户图片仅通过本地路径测试，不打包、不上传。
