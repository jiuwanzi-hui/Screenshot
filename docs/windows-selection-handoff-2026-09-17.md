# Windows 首次截图尺寸提示和松手闪屏

## 原因与修复

- 常驻进程的首次框选使用 GDI 轻量输入层；原先尺寸提示固定宽度并跟随鼠标，和编辑进程使用的选区左上角规则不同。现在两者共用 `SelectionSizeBadgeLayout`，按文字尺寸收缩宽度，屏幕边缘自动避让。放大镜仍跟随鼠标。
- 原先接收选区时，编辑层先开启没有选区孔洞的全屏遮罩，再设置选区；完成编辑初始化还会重新抬高 WPF 窗口，造成遮罩层级变化。现在先设置有效选区，再发布遮罩；已有输入焦点时不重复抬升窗口。
- 冷启动保留常驻进程的冻结画面作为临时覆盖窗口，编辑窗口及遮罩在其下完成布局与首帧绘制。遮罩显示与层级一起提交，避免重复压暗旧画面。收到 WPF 首帧事件后主动完成原生遮罩绘制，在后台等待 DWM 提交，再撤去临时覆盖层。
- 组合回归发现 WPF 还可能在首帧事件后提交一次置顶操作，将自己的画面放到遮罩前面。现在在 `WM_WINDOWPOSCHANGING` 中直接约束本次编辑窗口保持在遮罩下面，避免先露出未压暗画面、再补修层级。
- 取消时解除临时窗口所属关系，不销毁另一进程的输入层；交接完成后销毁常驻框选窗口和 DIB，不保留整屏缓存。
- 修改仅覆盖 Windows；非交接场景沿用原遮罩显示路径，不调整长截图算法或 macOS。

## 验证

- Release 相关回归 71 项通过，包含尺寸布局、8 个主题、100% / 125% / 150% / 200% 缩放、负坐标显示器、取色、输入接管、选区移动和取消。
- 新增桌面回归使用实际冻结桌面，不显示彩色测试图，也不注入全局键鼠。采样选区内部和外部遮罩：修复前捕获到最大 71 级 RGB 亮度跳变；修复后首次、再次交接采样的最大通道差均为 0。
- 最终组合回归的本机交接测量为 352 ms、206 ms，含测试中的编辑器创建；不是快捷键首帧时间，也不代表其他硬件性能保证。
- 真实独立工作进程验证了本地管道的框选交接、编辑器取得键鼠输入、关闭后退出（一次实测约 2.1 秒）。
- 桌面测试宿主没有真实快捷键给予的前台激活权限；跨进程测试在建立起始测试窗口时短暂附接前台输入线程，立即解除后再验证正常的前台授权与交接。未向产品加入此测试辅助逻辑。
- 在首帧呈现前关闭编辑器，确认不发送“已就绪”通知，常驻框选窗口仍由原进程拥有和释放。
- 没有添加生产调试日志、常驻定时采集、强制 GC 或清空工作集。
- 最终回归记录：`artifacts/verification/selection-handoff/selection-handoff-latest.trx`。
- 重新构建 4.1.0 Windows 包：安装 EXE 99,704,287 字节，便携 7z 96,960,643 字节。打包更新回归 48 项通过、1 项显式联网 Gitee 测试默认跳过；附件元数据、双源地址、大小、SHA-256 及 ZIP / 7z 完整性校验通过。没有远程发布。
