# Windows 常驻框选与交流群二维码（2026-09-16）

仅修改 Windows；不改 Mac 或长截图拼接算法，不发布或推送源码。

## 截图响应与空闲内存

上一版释放 WPF 功能进程后，每次快捷键截图需要等待进程与界面冷启动。本次普通键盘截图由常驻进程先在后台取得原始桌面像素，再创建轻量 Win32 框选窗口。首屏出现后并行启动功能进程；鼠标框选、窗口吸附、颜色取样和 Esc 不等编辑器加载。选区和同一帧原始像素通过当前用户管道交给原有编辑器，继续执行自动 OCR、标注和导出。

原生框选只在本次操作持有 GDI DIB；交接、取消、失败后销毁 HWND、DIB、DC、画刷和字体，不缓存整屏。采集有五秒等待上限，取消不等待显示驱动，迟到的帧会释放。全屏 HWND 首次显示前设置 NonRudeHWND。使用真实显示 DC 创建兼容 DC，使采集线程退出后界面线程仍可绘制；依据 [Microsoft CreateCompatibleDC](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-createcompatibledc) 的线程生命周期说明，并加入线程退出后的实际 BitBlt 回归。

当前“墨湾流光”主题原先在常驻进程预生成并持有两张 1000×1000 背景纹理。常驻色板改用同一组绘图指令的冻结矢量画刷；功能进程仍保留原有纹理和缩放策略。64×64 离屏像素对比检查显示图案保持一致，没有关闭悬浮按钮、改主题或降低截图分辨率。

托盘菜单还曾额外保存一张 1000×1000 GDI 位图及其生成过程的临时副本。现仅在绘制菜单时按实际像素尺寸生成，同一尺寸只生成一次，关闭菜单释放；保留相同图案、配色和文字对比。

本机 2560×1440、125% 缩放的测试计时从 App.SendFeatureAsync 到 Win32 首次 WM_PAINT 完成，包含后台抓屏。它不包含物理键盘驱动、桌面合成下一次呈现和测试工具注入延迟，不是零延迟或所有硬件的保证。编辑工具与 OCR 仍在功能进程按需加载，不能把框选首屏时间当作编辑器或识别完成时间。

内存使用专用工作集（MiB，1 MiB = 1,048,576 字节）判断空闲目标，同时保留总工作集与专用提交量。活动截图会持有真实像素，识别、录屏等也会增加内存；40 MiB 不是运行期间硬上限。没有清空工作集、设置内存硬上限或常驻预加载功能界面。

### 最终测量

最终探针使用墨湾流光，限制两颗逻辑核心及 `DOTNET_PROCESSOR_COUNT=2`，六次均从功能进程已退出的状态发起。第 1／3／5 次取消，第 2／4／6 次将 640×360 选区交给原编辑器；检查原图仍是 2560×1440、选区坐标不变、编辑画布已有图像，关闭后六个功能进程均退出，快捷键均恢复。

| 六轮首屏绘制 | 56.0／43.4／47.0／44.6／47.1／43.6 ms |

原始数据为 `native-delivery-run.txt`、`native-delivery-memory.csv`。仅代表本机受控 CPU 预算，不等价于低配 CPU、不同显卡／多屏／高分辨率等所有硬件。编辑器交接约 951～1023 ms，其中包含探针主动等待 350 ms 才提交选区；它与 43～56 ms 的可操作框选首屏分开报告。
