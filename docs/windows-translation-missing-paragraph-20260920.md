# Windows 技术说明段落漏译修复（2026-09-20）

## 复现与原因

用户截图顶部保留英文，状态为“部分段落未完成，已保留原文”。从截图中原文区域做 PP-OCRv6 small 识别，并与 README 中相同原文对照。

Hy-MT2 1.8B 在整段翻译中遗漏旧版本号 `1.0.0` 及旧数据路径；原有拆句补译仍遗漏 `1.0.0`。完整性数字校验正确拒绝结果，于是整个段落保留英文。TranslateGemma 在无保护的原始输出中也曾省略完整路径的一部分，但仅数字校验无法发现路径丢失。增加一般性的“保留数字与路径”提示仍未解决 Hy 的漏译。

这复现了用户看到的行为，不是因为显卡配置不足，也不是这段未送给模型。未取得用户那次操作的悬停错误详情，因此不能将本机复现等同于那次请求的原始日志。

## 改动

- Windows 离线模型的单次请求自动识别明确的点分版本号、Windows 路径和已知扩展名文件名，用无数字、请求独立的占位符保护，并提供 JSON 字段含义。
- 返回时检查每个占位符的出现次数，拒绝缺失、重复或未知占位符；通过后原样还原，再走既有语言及数字完整性检查。不能用补齐数字、放宽校验来伪造成功。
- 首次翻译及失败拆句补译共用保护；正常处理不新增推理请求，不改变模型、提供方顺序、上下文预算、资源调度及空闲释放。
- 单独选中的描述性文件名（如 `UserSettings.json`）仍按原有标签规则翻译，避免把用户想翻译的单词变成不可译内容。实时术语占位符与普通请求的保护映射彼此隔离。

- 原文及真实截图 OCR 结果分别经过 Hy-MT2 1.8B 与 TranslateGemma 4B，首次及连续两次共六次请求均成功；版本 `2.8.3`、`1.0.0`、路径 `%LocalAppData%\Screenshot` 与 `ScreenshotData` 完整，安装、备份、迁移和删除步骤均有译文，相邻中文段落不变，无再次拆句补译。
