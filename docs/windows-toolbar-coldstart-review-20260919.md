## 本机调用栈与被撤回的实验

通过仅作用于测试子进程的 DOTNET_DiagnosticPorts，从启动前采集 .NET 线程采样。记录为 `artifacts/4800h-trace-20260919-0932/*profile*.nettrace` 及 `*-start*.nettrace`。采样本身有开销，不能把它的时间作为产品性能数字。

可见的本机等待包括 RenderCapability/Visual 触发图形通道初始化，进入 `MediaContext.CompleteRender -> DUCE.Channel.SyncFlush`，单段约 96–105 ms；HwndTarget.OnResize 又进入同一同步路径，约 64 ms；另有 WPF 输入设备、IME、XAML 与隐藏调色板初始化。原生时间无法由该采样进一步拆为具体驱动、系统等待或计算，因此不将这些本机调用栈当成 4800H 的根因证明。

尝试过：拆分工作进程和完整应用启动、用原生消息窗口代替 HwndSource 快捷键窗口、延后不需要的渲染档位查询、按需创建调色板。普通 Release 局部启动变短，但实际单文件交付包的完整冷启动没有明确收益：
